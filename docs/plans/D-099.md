# D-099: harness 완료 아카이브 건강 검사

## 1. 명제와 코드 전제

읽을 수 있는 빈/중복/손상 완료 아카이브가 `--check`에서 정상으로 출력되거나, 명시 base의 조회 실패와 예상치 못한 ID 감소가 조용히 정상 처리되면 미완이다. 일반 건강 검사만으로 과거 내용 보존이나 부채 전체 완료를 증명한다고 표현해도 미완이다.

기준 main `4a4a36a12a3d914d6bc0379ded94bc0123c4d370`의 실제 `scripts/harness-context.sh`를 확인했다.

| 전제 | 소스/기록 확인 |
|---|---|
| 현재 완료 archive 읽기 | `read()`는 읽기 예외만 problems에 추가한다. 빈 문자열과 완료 D행 최소/유일성은 검사하지 않는다. 완료 수는 두 파일의 마지막 status cell에 ✅가 있는 줄의 합계다. |
| 기존 check | TASKS 현재 단계/ADR 행/progress heading/git log만 확인하며 `ok — 모든 구획을 읽었다`를 출력한다. base 비교 인자는 없다. |
| 실제 소실 이력 | D-053 완료 반영 `d5f1a2ac`에서 TASKS-done 원문이 67553B/59줄/D행44에서 875B/2줄/D행1로 바뀌었다. 복구 `bf678c0c`는 68427B/60줄/D행45다. D행 모집단과 전체 text 줄 수를 구분한다. D-052 최초 분리 사건으로 바꾸지 않는다. |
| 승인된 정상 변화 | 새 부채 등록과 TASKS에서 done 표로의 완료 행 이동, plan/audit의 done 폴더 이동은 정상이다. digest의 root plan 개수 감소 자체를 소실로 판정하지 않는다. |

등급 M: 공유 CLI의 검증 계약과 CI 소비를 보강한다. inline Python과 shell entrypoint를 유지하고 새 외부 의존성·제품 아키텍처/환경 변화가 없으므로 새 ADR은 불필요하다. D-098 구현에는 의존하지 않는 main 기반 독립 PR이다. D-098은 ordered 본문/이동 보존, D-099는 현행 건강 및 명시 base의 ID 감소 감지다.

## 2. 작업 항목

- [x] P1. standalone 건강 검사에서 완료 archive의 필수 heading/table/최소 D행과 두 task 파일 D-ID 유일성을 검사한다. 잘못된 형식/읽기 실패는 exit3으로 전파하며 부채 완료 의미로 확장하지 않는다.
- [x] P2. `--check --base <commit>`에서 실제 git source를 읽고 base의 task ID 손실/완료 archive 행 감소를 거부한다. base/문서 조회 실패를 현재 상태 정상으로 대체하지 않는다. 정상 추가/완료 이동과 plan archive 감소는 통과한다.
- [x] P3. 실제 entrypoint를 임시 git fixture에서 실행해 빈/누락/중복/형식오류/감소/조회실패와 정상 추가/보존 이동을 paired control로 검증한다. 실제 D-053 overwrite bytes와 복구 source도 고정 git 이력에서 재현한다.
- [x] P4. 독립 CI named step `Harness archive health`에서 명시 PR base/push before와 자기검증을 실행한다. CLI 도움말/성공 메시지와 own 문서에 standalone/base 비교의 한계를 명시한다. D-104의 기존 설명/counts 원문은 변경하지 않는다.

## 3. 검증

Gradle/Docker/운영 명령 없이 임시 로컬 git fixture와 `harness-context.sh` 실제 CLI를 사용한다. 정상 baseline·신규 D행·완료 이동·계획 archive, 빈 파일·파일 누락·중복 및 겉보기 정상인 감소·unreadable base를 각각 대조한다. 기준 조회를 무시하는 구현이나 항상 정상 반환하는 구현을 음성 대조로 거부한다. 역사 소실 자료는 git object를 읽어 temp tree에 적용하며 root 원문을 변경하지 않는다.

전체 PR CI와 root가 배정할 정확 head 독립 검토는 별도로 기다린다. 별도 Codex 리뷰 미호출. 공유 TASKS/PHASE/master/ADR index는 root 소유이며 편집하지 않는다.


## 구현 결과

inline entrypoint와 명시 base/standalone 계약을 구현했다. 실제 CLI fixture 33개, 잘못된 구현 9개 대조 및 기존 CI 구조 lint 3개, shell syntax/whitespace 검사를 통과했다. 기존 main4a4 checker가 실제 875B 덮어쓰기 원문을 잘못 받아들이고 수정 checker가 거부하는 대조와 복구 정상도 확인했다. artifact는 `docs/plans/evidence/D-099/`에 보존한다. 전체 CI와 독립 정확 head review는 PR에서 대기하며 공유 완료 문서는 root가 관리한다.

## 독립 검토 후 경계 수정

초기 head `c9330783e6a25e00a318fc07952872b9e855eca9`의 33 fixture/9 mutant 기록은 당시 구현의 결과다. 독립 검토가 추가 빈 마지막 cell(`✅ ||`)의 잘못된 통과와 CI shallow 조회 실패(rc23)의 삼킴을 발견했다. optional border 하나만 제거하고 escaped pipe를 delimiter와 구분하며, 조회 rc와 출력값(true/false)을 분기 전에 검증하도록 수정했다.

새 paired control은 optional border 유무/본문 code pipe·escaped pipe/추가 빈 status, 정확 YAML run body의 shallow/full 정상·query23·fetch23·예상 외 출력·빈 base·건강 검사 실패를 다룬다. 전체 대상은 selftest 40 method와 CLI 10개/workflow 5개 mutant다. 로컬에서는 원래 두 결함의 최소 2 method만 통과했다. 사용자 Actions 우선 지시에 따라 전체 40/15와 전체 PR CI는 GitHub Actions에서 검증하며 아직 통과로 기록하지 않는다.
