# D-081 — 수동 리스너 기동의 할당 대기 (D-082 공동 구현)

## 명제 / 코드 검증
수동으로 기동한 DLQ 리스너가 할당되기 전에 발행하거나, 공백·콜론 opt-in 및 수동 기동의 대기 누락이 lint를 통과하면 미완이다.

| 코드 전제 | 확인 결과 |
|---|---|
| DlqReplayEntrypointIntegrationTest.setUp | dlq-*만 MessageListenerContainer::start, 할당 대기 없음 |
| AbstractIntegrationTest.awaitListenerAssignment | registry 전체에 running + 할당 non-empty 요구. 그대로 호출하면 의도적으로 정지한 업무 리스너 때문에 timeout |
| ITC-006 | 정확한 enabled=true 문자열만 검사, 주석 속 helper 문자열로 우회 가능 |

공유 testFixtures overload와 order 테스트를 수정하므로 M. 기존 ADR-0029 D3/D4, D-058 계약의 집행이며 새 아키텍처 결정은 없어 ADR 신설 불필요. 별도 Codex 리뷰 미호출.

## 작업 항목
- [x] P1. 명시적으로 선택한 리스너 컬렉션을 기다리는 helper overload 추가, DLQ 테스트에서 같은 컬렉션을 시작하고 대기.
- [x] P2. 주석/문자열을 구분해 opt-in 표기 변형 및 listener 타입·registry에 연결된 수동 start 검사. 무관한 server/container start 제외.
- [x] P3. positive/negative self-test, lint, 대상 JVM 테스트 검증.
- [x] P4. 메인 통합 후 전체 ./gradlew test 및 관련 lint 검증.

## 검증
수동 method reference/직접 start/registry start에서 대기 호출을 제거한 fixture는 ITC-006. 주석/문자열 속 가짜 호출도 실패. 공백·콜론 opt-in도 실패. 정상 helper, false 속성, 무관한 start는 통과. 실제 DLQ 통합 테스트는 선택된 리스너 할당 후 replay 경로를 검증한다. 메인이 Gradle 자원을 조율하고 통합 후 ./gradlew test를 실행한다.

## 미해결 / 범위 밖
Java AST·상속·동적 프로퍼티 데이터 흐름 전부를 해석하는 분석기는 범위 밖. 저장소 인라인 속성과 명시적 listener/registry 기동 형태를 정적 검사한다. D-080 수치 정정과 D-083 cleanup 예외 처리는 별도 작업으로 유지.
