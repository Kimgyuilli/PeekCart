# D-092 계획 조사

## 2026-10-21 계획 전 코드 확인

- 등급 M. Grafana provisioning, notification-service caller 설정, 운영 문서를 다루며 public API·event schema·DB schema는 변경하지 않는다.
- `grafana-alerts.yml`의 `signal` label과 GKE/minikube values를 확인했다. contact point/notification policy는 repo에 없다.
- `NotificationCommandService`와 `NotificationKafkaConfig`는 같은 `SlackPort`를 사용한다. `SlackNotificationClient`는 단일 URL이고 Outbox/DLQ 공통 호출도 이 포트다.
- `OutboxPollingService`는 max retry 뒤 `FAILED`로 저장하고 repository는 `PENDING`만 poll한다. entity에 재개 메서드나 Outbox 재발행 runbook은 없다.
- 계획은 local receiver/provisioning 검증과 실제 Slack/GKE/운영 DB 재개 조건을 분리한다. product code, live channel, production DB, paid infrastructure를 실행하지 않았다. 별도 Codex 리뷰 미호출.

## 2026-10-21 구현 부분 검증

- PR scope는 provisioning/runbook/fixture 일부만 포함한다. P1 local Grafana receiver runtime과 P3 MySQL CI 검증은 실행 전이라 미완료이고, P2 사용자/운영 app `SlackPort` 분리는 별도 작업이다. D-092 전체는 열린 상태다.
- P1: Grafana `signal=outbox-publish|dlq` 두 신호를 같은 `peekcart-operations` Slack contact point에 연결하는 policy를 shared ConfigMap으로 provisioning한다. GKE/minikube는 URL을 optional Secret `grafana-ops-webhook/url`에서 읽으며 저장소에는 credential이 없다. local Grafana fixture 생성기는 contact point/policy를 provisioning하고 loopback receiver stub을 목표로 한다.
- P3/P4: Outbox `FAILED` 단일 DOMAIN/legacy 조건부 SQL, 중복 payload 중단, 모든 consumer 멱등성 근거, producer writer 동결, transaction/poller 통제 및 승인 경계를 runbook에 적었다. 앱 상태 전이 코드나 운영 DB 변경은 넣지 않았다.
- 검증: `scripts/d092-ops-fixture.py`, `scripts/monitoring/verify_alerts.py --output ...`, `kubectl kustomize k8s/monitoring/shared`, `scripts/kustomize-namespace-lint.sh`, `git diff --check` 통과.
- 검증: SQLite fixture는 논리 가드만 확인한다. MySQL 8 test가 runbook SQL/JSON preflight와 duplicate guard를 확인하며 PR217 notification-service shard에서 통과했다. D-092 script는 runbook과 Java test SQL parity 및 duplicate-preflight removal mutant를 확인한다.
- 범위 한계: PR217 전용 50분 제한 Actions job을 추가해 기존 Grafana `--run` fixture의 실제 loopback route와 default-route 누수 대조를 수행한다. 첫 exact-head 실행은 D-093 readiness 경쟁으로 route assertion 전에 실패해 P1 증거가 없다. GKE, 실제 Slack, production DB/SQL은 실행하지 않았다. MySQL test도 동시 writer freeze·운영 절차·잠금 안전성을 증명하지 않는다. 별도 Codex 리뷰 미호출.
