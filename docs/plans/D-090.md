# D-090: Outbox FAILED 알림 실행 계약 검사

## 1. 명제
Outbox FAILED 규칙의 PromQL A가 유지되어도 실행 조건·임계·대기시간·중지 상태·라우팅 라벨 변이가 CI를 통과하면 미완이다.

### 코드로 확인한 배경
| 전제 | 확인 결과 |
|---|---|
| `grafana-alerts.yml`의 `peekcart-outbox-failed` | `condition: B`, A의 instant=true/range=false, B의 math `$A > 0`, `for: 5m`, severity=warning/signal=outbox-publish를 사용한다. `isPaused`는 생략되어 기본 활성 상태다. |
| `observability-promql-lint.sh` | Outbox 계약에는 metric/apps/expr만 있다. 캐시/승인 규칙에 이미 존재하는 condition/for/labels 검증을 재사용할 수 있다. |
| 기존 self-test | Outbox 삭제/status 변이만 검사한다. `run_case`는 모든 nonzero를 성공으로 보므로 새 변이는 exit 1과 해당 계약 진단을 함께 검사한다. |
| 기존 검증 한계 | D-063은 실제 로컬 evaluator 증거이며 이 작업은 CI 정적 회귀 공백을 닫는다. 외부 알림 전달을 증명하지 않는다. |

등급 M: CI가 강제하는 공유 alert 계약 검사 표면을 확장한다. 제품 규칙의 값·평가 동작은 바꾸지 않으며 새 의존성·인프라·경계가 없어 ADR 추가는 없다. 기존 ADR-0019의 PromQL 정본 정책을 유지한다.

## 2. 작업 항목
- [x] P1. 기존 Outbox A/B·condition·for·labels 계약을 lint 정본에 추가하고 활성 상태 및 평가 데이터 구조도 검사한다. `isPaused` 생략과 명시 false는 정상으로 허용한다.
- [x] P2. Outbox 실행/라우팅의 독립 음성 변이를 추가한다. 각 변이는 exit 1과 해당 UID/계약 진단이 있어야 성공이며 원본 및 명시적 활성 대조군은 통과해야 한다.
- [x] P3. 원본·변이·기존 self-test와 관련 lint를 실행하고 결과 및 한계를 audit/PR에 기록한다.

## 3. 검증 방법
- P1/P2: signal=dlq, isPaused=true, B=`$A > 999`, for=500m를 각각 주입해 먼저 기존 검사 exit 0을 재현한다. 수정 후 네 변이는 모두 해당 계약 위반 exit 1이어야 한다.
- P2: condition=A, A/B refId 변경, B 삭제/추가·type/datasource 변경, instant/range 변이도 각각 실패해야 한다. 정본과 `isPaused: false`는 promtool syntax까지 통과해야 한다.
- P3: `bash scripts/observability-promql-lint.sh` 및 `--self-test`, `bash -n`, `git diff --check`, ship preflight, consistency/writing lint를 확인한다. 전체 테스트는 공유 자원 지시에 따라 동일 SHA의 GitHub Actions test shards 및 전체 CI로 검증하며 대기를 통과로 적지 않는다.

## 미해결 / 범위 밖
- D-093의 evaluator 초기 준비 경쟁은 별도 PR로 처리한다. 이 작업은 실제 evaluator 실행 조건의 정적 계약이며 NoData·실제 series·외부 전달을 보장하지 않는다.
- 다른 alert의 실행 조건 확대는 이번 Outbox 범위 밖이다. 해당 규칙의 변경 때 별도 계약 및 음성 대조군을 추가한다.
- root 소유의 TASKS·PHASE5·ADR index·총괄 계획은 수정하지 않는다.
