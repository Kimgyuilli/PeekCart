# D-083 Kafka cleanup 실패 전파

## 1. 명제

토픽 부재 이외의 describe 실패가 숨겨져 잔여 레코드가 있는 상태로 테스트가 진행되면 미완이다.
공용 fixture 계약을 수정하므로 M이며, 되돌림은 common의 fixture/회귀 테스트로 국한된다.

| 코드 전제 | 확인 | 처리 |
|---|---|---|
| AbstractIntegrationTest.cleanKafkaTopics | 모든 Exception을 continue로 삼킴 | KafkaFuture.get의 ExecutionException 중 UnknownTopicOrPartitionException만 생략 |
| 외부 catch | InterruptedException에 interrupt 복구, 그 외 cleanup 실패 래핑 | 그대로 유지하며 회귀 검증 |
| 서비스 호출자 | bootstrapServers와 topic 이름을 전달 | 호출 계약과 deleteRecords 경로 유지 |

ADR 판단: 새 외부 의존성·경계·인프라가 없다. ADR-0028 공유 컨테이너 cleanup 계약과 D-028의 부재 예외 분류를 복구하므로 새 ADR 불필요.

## 2. 작업 항목

- [x] P1. describe 실패 분류를 좁히고 interrupt 복구를 보존한다.
- [x] P2. 부재·timeout·권한 오류·interrupt를 주입하는 회귀 테스트로 정상 생략과 즉시 실패를 구분한다.
- [ ] P3. 전체 CI와 독립 PR 검증 뒤 root 병합·완료 기록을 확인한다.

## 3. 검증 방법

- common KafkaTopicCleanupTest: Admin 생성 경계를 mock하여 실제 cleanKafkaTopics를 호출한다. Docker/SharedContainers 기동이 없다.
- UnknownTopicOrPartitionException만 정상 반환. timeout·authorization은 cleanup 실패와 원인이 드러나야 한다.
- InterruptedException은 호출 실패 및 현재 스레드 interrupt flag 복원을 함께 확인하고 테스트 뒤 flag를 정리한다.
- 이 분기는 예외 분류 계약이므로 mock이 증거이며 DB/브로커 원자성 증거로 주장하지 않는다.
- 전체 모듈 build/test·root guards·필수 gate는 사용자 승인대로 같은 SHA의 무료 CI 증적으로 충족한다.

## 미해결

집중 회귀 4건 통과(2026-10-17, Gradle 11초). 원격 실행은 root 무료 조건 확인까지 보류. D-068/D-080은 별도 계획이며 이 계획의 완료에 포함하지 않는다.
