# 기존 PR 본문 문체 재작성 (PR 1~124)

## 1. 명제

다음 중 **하나라도** 성립하면 미완이다.

- 대상 PR 의 제목 또는 본문이 `scripts/writing-lint.sh --file` 에서 오류를 낸다
- 재작성된 본문에 **원문에 없던 사실**이 들어갔다 (수치, PR 번호, 파일 경로, 결론)
- 원문에 있던 링크, 부채 ID, ADR 번호, 측정 수치가 소실됐다
- 코드펜스 안의 인용 출력이 변경됐다
- 커밋 메시지를 건드렸다 (범위 밖이다)
- 백업에서 원문을 복원할 수 없다

## 2. 배경

### 왜 하는가

`docs/conventions/writing.md` 를 2026-09-19 에 도입했다 (PR #125). 그 이후 작성물은 규약을
따르지만 이전 PR 124개는 따르지 않는다. 포트폴리오 레포라 PR 본문이 읽히는 산출물이다.

### 착수 전 실측 (2026-09-19, 백업 기준)

| 위반 | 건수 | PR 수 |
|---|---|---|
| em/en dash | 1,364 | 115 |
| 화살표 | 885 | 113 |
| 수학기호 | 106 | 37 |
| 이모지 | 194 | 41 |
| Claude 트레일러 | 0 | 0 |

제목: 형식 위반 26개 · 60자 초과 50개 · 추적 태그 9개.
본문 총량 612KB. 대상 PR 124개 (머지 122, 열림 1, 그 외 1).

### 기계 치환이 안 된다

`A — B` 를 쉼표로 바꿀지 마침표로 끊을지 괄호로 넣을지는 문장을 읽어야 정해진다. 화살표도
"A 에서 B 로" 인지 "A 이면 B" 인지 문맥이다. 일괄 치환하면 어색한 한국어가 2,000군데 생긴다.
**LLM 이 읽고 다시 쓰는 작업이다.**

### 커밋 메시지는 범위 밖이다

머지된 커밋 메시지는 main 히스토리를 다시 쓰지 않는 한 바꿀 수 없다. 사용자가 바꾸지 않기로
결정했다. 결과적으로 커밋 로그에는 em dash 가 남고 PR 본문만 정돈된다. **의도된 상태다.**

### 코드펜스는 건드리지 않는다

펜스 안 93건(23개 PR)은 명령 출력과 로그를 그대로 인용한 자리다. 고치면 인용이 사실과
달라진다. `writing-lint` 가 펜스를 건너뛰도록 이미 수정했다 (self-test 11건).

## 3. 작업 항목

- [ ] P1. 백업 무결성 확인. `.cache/pr-backup-latest` 가 가리키는 디렉터리에 `all.json` 과
      `<번호>.title` / `<번호>.body` 가 124쌍 있는지 센다. 없으면 다시 뜬다
- [ ] P2. 복원 스크립트 작성. 백업에서 원문을 되돌리는 경로를 **먼저** 만든다.
      되돌릴 수 없는 상태로 124개를 고치지 않는다
- [ ] P3. 배치 1 (최신 10개: #125 제외, #124 부터 역순). 제목과 본문 재작성
- [ ] P4. 배치 1 검증 후 사용자에게 결과 제시. 계속할지 확인
- [ ] P5. 나머지를 10개씩 배치로 반복. 배치마다 검증
- [ ] P6. 전수 재검사. 124개를 다시 받아 `writing-lint --file` 오류 0건 확인
- [ ] P7. 사실 보존 대조. 원문과 재작성본에서 링크/수치/ID 집합이 같은지 기계 비교

## 4. 검증 방법

항목별로 **실패를 주입한 뒤 확인**한다. "고쳤다" 는 검증이 아니다.

| 항목 | 주입 | 통과 기준 |
|---|---|---|
| P2 | 임의 PR 하나를 망가뜨린 뒤 복원 | 본문이 백업과 바이트 동일 |
| P3 | 재작성본을 lint 에 넣음 | 오류 0. 경고는 허용 |
| P7 | 원문/재작성본에서 `pull/\d+`, `#\d+`, `[A-Z]+-\d+`, 숫자+단위 추출 | 집합이 원문 ⊇ 재작성본, 신규 0건 |
| P7 | 코드펜스 블록 추출 후 비교 | 펜스 내용 바이트 동일 |
| 전체 | 커밋 해시 비교 | `git log origin/main` 이 착수 전과 동일 |

## 5. 절차 (PR 1개당)

1. 백업에서 원문을 읽는다. **GitHub 에서 다시 받지 않는다** (이미 고친 것을 또 고치지 않기 위해)
2. 제목: `<type>(<scope>): <명사형>` 60자 이내. 추적 태그는 본문 마지막 `Refs:` 줄로
3. 본문: 어미를 "~습니다" 로 통일. em dash 는 쉼표/마침표/괄호로, 화살표와 수학기호는 말로 푼다.
   이모지는 텍스트로. 볼드는 구획당 2개 이하. 수사("한 단계 더 나쁘다")는 사실 서술로
4. **코드펜스 안은 한 글자도 바꾸지 않는다**
5. `scripts/writing-lint.sh --file <임시파일>` 오류 0 확인
6. `gh pr edit <번호> --title "..." --body-file <임시파일>`
7. 다시 받아 lint 재확인

## 6. 원칙

- **형식만 바꾼다.** 사실, 결론, 수치, 판단은 원문 그대로다
- 원문이 모호하면 **원문에 가깝게 둔다.** 다듬으려다 없던 주장을 만들지 않는다
- 원문에 없는 절(이월, 등급 등)을 새로 만들지 않는다. 그때 없던 개념이다
- 한 배치가 끝날 때마다 멈추고 보고한다. 중간에 중단해도 손해가 없어야 한다

## 7. 미해결

- **오래된 PR 은 당시 맥락이 없다.** 문장이 무슨 뜻인지 불확실하면 형식만 최소로 고치고
  그 PR 을 목록에 남겨 사용자에게 보고한다
- **`gh pr edit` 는 편집 이력을 남긴다.** GitHub UI 에 "edited" 로 표시된다. 되돌릴 수는
  있으나 편집 사실 자체는 지워지지 않는다
- 제목 변경은 머지 커밋 제목과 어긋난다. 위 "커밋 메시지는 범위 밖" 참조
