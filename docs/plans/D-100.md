# D-100: Flyway 체크섬 근거 버전 정정

## 1. 명제

D-050과 PHASE5가 실제 프로젝트에서 해석되는 Flyway 버전이나 `ChecksumCalculator`가 SQL 줄을 처리하는 범위를 잘못 설명하면 미완이다.

| 코드 검증 전제 | 확인 결과 |
|---|---|
| #169 직전 `42030ff`와 현재 기준 코드 `be535c57`의 payment runtimeClasspath | Flyway 의존성 버전은 `11.7.2`; 당시 로컬 `12.4.0` jar 확인은 프로젝트 해석 결과가 아니다. |
| 두 버전의 `ChecksumCalculator` | raw `javap`와 jar 실행 결과에서 동일 입력은 동일 checksum. 실험의 comment text와 공백-only 줄은 checksum이 바뀌고, 빈 줄, CRLF, 마지막 개행 제거는 바뀌지 않는다. |
| 데이터베이스 검증 범위 | 실험은 `StringResource` 입력의 calculator 실행이다. DB에 적용된 migration의 `validate` 재실행은 하지 않았다. |

등급 S: D-050의 기록과 PHASE5 사실 설명을 좁게 보정하는 문서 변경이다. Flyway 동작, migration 파일, 애플리케이션 코드는 변경하지 않는다.

## 2. 작업 항목

- [x] P1. 실제 runtimeClasspath와 두 jar의 checksum 관찰 결과를 과거 계획 근거와 대조한다.
- [x] P2. D-050 및 PHASE5에 프로젝트 버전, 줄 처리 세부사항, 미실행 DB validate 경계를 Update Log/사실 보정으로 남긴다.

## 3. 검증 방법

| 항목 | 검증 |
|---|---|
| P1 | [보존한 과거 로그와 새 dependency report](evidence/D-100/README.md)를 git 설정 이력과 대조했다. 두 jar를 `javap`로 확인하고 독립 Java probe로 동일 8개 입력을 실행했다. 입력·CRC·jar SHA-256·재현 명령을 같은 근거 문서에 남겼다. |
| P2 | D-050 및 PHASE5의 기존 설명을 보존하면서 보정 문구가 CRC32의 입력 행 처리와 DB validate 미실행을 정확히 구분하는지 검토한다. |
| 문서 | `git diff --check`, plan grade/preflight/consistency, writing lint를 실행한다. |

## 미해결

- 기존 DB에서 실제 `flyway validate`를 실행해 영향 여부를 확인하는 작업은 포함하지 않는다. checksum 변이 실험은 isolated `StringResource` 대상이다.
- TASKS 완료 상태와 ADR 인덱스는 root가 관리한다.

## 검증 결과

- 2026-10-21: 두 jar의 8개 입력별 CRC와 bytecode 기록 대조 통과. 새 offline dependencyInsight 성공, `11.7.2` 선택.
- `git diff --check` 통과, plan grade S, ship preflight `ok`, consistency `ok` (0 warnings). 커밋·PR 제목·PR 본문의 writing lint는 출하 시 검사한다.
- 전체 `./gradlew test`는 로컬에서 실행하지 않았으며 PR의 전체 CI 결과로 확인한다. 실제 DB validate는 범위 밖이다.
