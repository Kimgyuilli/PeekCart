# D-100: Flyway 체크섬 근거 버전 정정

## 1. 명제

D-050과 PHASE5가 실제 프로젝트에서 해석되는 Flyway 버전이나 `ChecksumCalculator`가 SQL 줄을 처리하는 범위를 잘못 설명하면 미완이다.

| 코드 검증 전제 | 확인 결과 |
|---|---|
| #169 직전 `42030ff`와 현재 `origin/main`의 payment runtimeClasspath | Flyway 의존성 버전은 `11.7.2`; 당시 로컬 `12.4.0` jar 확인은 프로젝트 해석 결과가 아니다. |
| 두 버전의 `ChecksumCalculator` | raw `javap`와 jar 실행 결과에서 동일 입력은 동일 checksum. comment text와 공백-only 줄은 checksum이 바뀌고, 빈 줄, CRLF, 마지막 개행 제거는 바뀌지 않는다. |
| 데이터베이스 검증 범위 | 실험은 `StringResource` 입력의 calculator 실행이다. DB에 적용된 migration의 `validate` 재실행은 하지 않았다. |

등급 S: D-050의 기록과 PHASE5 사실 설명을 좁게 보정하는 문서 변경이다. Flyway 동작, migration 파일, 애플리케이션 코드는 변경하지 않는다.

## 2. 작업 항목

- [x] P1. 실제 runtimeClasspath와 두 jar의 checksum 관찰 결과를 과거 계획 근거와 대조한다.
- [x] P2. D-050 및 PHASE5에 프로젝트 버전, 줄 처리 세부사항, 미실행 DB validate 경계를 Update Log/사실 보정으로 남긴다.

## 3. 검증 방법

| 항목 | 검증 |
|---|---|
| P1 | `docs/learning/drafts/tools/blog32/flyway/historical-dependency.log`와 현재 `:payment-service:dependencyInsight --dependency org.flywaydb:flyway-core --configuration runtimeClasspath`가 11.7.2를 선택하는지 대조한다. `javap-*.txt`, source copies, and `checksum-11.7.2.log`/`checksum-12.4.0.log` compare both jars over 8 inputs. |
| P2 | D-050 및 PHASE5의 기존 설명을 보존하면서 보정 문구가 CRC32의 입력 행 처리와 DB validate 미실행을 정확히 구분하는지 검토한다. |
| 문서 | `git diff --check`, plan grade/preflight/consistency, writing lint를 실행한다. |

## 미해결

- 기존 DB에서 실제 `flyway validate`를 실행해 영향 여부를 확인하는 작업은 포함하지 않는다. checksum 변이 실험은 isolated `StringResource` 대상이다.
- TASKS 완료 상태와 ADR 인덱스는 root가 관리한다.
