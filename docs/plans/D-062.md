# D-062 동일 DLT 좌표 재소비 E2E

## 명제

새 메시지를 재발행해 attempt 증가를 흉내내거나 group rewind 후 서비스 복원 없이 후속 시나리오를 실행하면 미완이다.
공유 E2E 실행 계약 변경으로 M, 기존 DLQ 원장 UNIQUE 계약 검증이며 새 ADR 불필요.
코드 확인: scenario D는 poison1회와 원장attempt1만 확인, runner에는Docker권한없음.

## 작업 항목

- [x] P1. D준비에서원장/원본6좌표와실제DLT좌표를저장한다.
- [x] P2. 외부shell이order-service정지후groupEmpty확인, runner에서동일DLT offset으로rewind,서비스재기동한다.
- [x] P3. 동일원장id/6좌표/행1/attempt2,committed offset회복과readiness/후속시나리오무간섭확인.
- [ ] P4. 실패중간복원·경량계약검증·실제CI·독립검증/root병합기록.

## 검증

재발행없음. DLT payload marker와failed_consumer_group header로해당DLT레코드만선택한다.
서비스정지뒤group active member0을확인하고한partition만rewind한다. 기존다른partitionoffset은보존한다.
성공후동일레코드1회재소비/후속offset까지회복을확인한다. 실패중간에도service기동및stackteardown을보장한다.

## CI 시간 및 정리

D의 정지/rewind/재기동 구간 상한은 480초다. CI 전체 45분 상한은 유지하며 실제 durations 증적을 확인하기 전 완료하지 않는다. 정지 표식은 바깥 teardown에도 남아 timeout/실패 때 `--keep` 여부와 무관하게 Order 재기동을 시도한다. 일반 실행은 이어 스택 전체를 정리한다. 성공 경로는 offset 회복과 전체 readiness 뒤 E/F를 실행한다.

기존 PR180 head e417b8a의 실제 CI38981330710에서 P1~P3가 검증되었다. 이후 app/main 통합 head에는 새 CI와 독립 검증이 필요하며 최종 P4는 열린 상태다. 상세 checkout·artifact·상태·시간은 audit에 보존한다.
