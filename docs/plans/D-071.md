# D-071 — 장바구니 상품 read model 조합

## 1. 명제
미수신 상품 때문에 item을 잃거나, 가짜 가격을 표시하거나, stale 이벤트가 최신 이름·상태·가격을 덮으면 미완이다.

## 2. 배경과 코드 검증
| 전제 | 실제 | 구현 |
|---|---|---|
| cart DTO는 id/productId/quantity | CartItemDto 세 필드 | nullable metadata 추가 |
| event name/status/price/version | ProductUpdatedPayload에 이미 존재 | 이벤트 무변경 |
| cache 단가만 보유 | ProductPriceCache 및 V1 DDL | V13 nullable 확장 |
| 역전 차단 | 원자 upsert version 비교, 멱등 consumer | metadata도 같은 판정 |
| 동일 타입 응답 3곳 | query/add/update | 동일 bulk 조합 |
| upsert 순서 | source_version 다음 updated_at이라 새 version에서 날짜 갱신 누락 | source_version을 마지막 갱신 |

공개 DTO·DDL·여러 레이어 영향과 롤백 고려로 L. ADR-0036 선행 작성. B1/B1b 이동 없음; B2 실제경로 확인; B3 기존 testFixtures 유지; B4 구체 조회/응답; B5/B6 모듈 변경 없음; B7/B9 version 원자갱신; B8/B10 새모듈 없음; B11 새메트릭 없음; B12 실제 MySQL 역전/같은version/동시업데이트 검증 필요.

## 3. 작업 항목
- [x] P1. ADR0036, nullable DDL, 원자 metadata upsert와 bulk repository 조회.
- [x] P2. query/add/update 응답 조합과 nullable availability·기존 필드 호환.
- [x] P3. 단위·슬라이스·실제 DB에서 미수신/가격만있는행/상태/역전/중복/동시갱신 검증.
- [ ] P4. 최신 CI·독립 검증·root 병합·기록.

## 검증 방법
cache missing과 null metadata 행을 넣어 item 유지·null가격/상태를 확인한다. 새/과거/같은version payload의 이름/가격/상태를 다르게 만들어 오래된 overwrite를 반증한다. 서로 다른 version을 동시에 소비해 가장 높은 version의 동일 묶음이 남는지 MySQL에서 검증한다. HTTP JSON의 기존 필드와 새 null필드를 확인한다. 로컬 heavy root 승인 전 실행하지 않고 전체 CI gate 대기 상태를 유지한다.

## 완료 조건과 미해결
root 승인에 따라 기존 item 유지와 정보 미수신 표시를 선택했다. 주문 정책은 기존 ORD007/009 유지. 더 높은 version이 오기 전 legacy 행 metadata는 null이며 명시적 migration 한계다. 원격 무료 조건 미확인으로 push/PR 보류. 모든 필수 증거 후에만 root 완료 기록.
