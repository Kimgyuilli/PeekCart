# D-070 — cache fallback 자동 alert

## 명제
get 지속 장애와 evict stale 창을 구분하지 않거나, 다른 서비스/캐시 신호가 섞이거나, 규칙을 무력화해도 lint가 통과하면 미완이다.

## 배경과 ADR 판단
기존 runbook은 get rate>0 10분, evict increase>=1 즉시를 규정하지만 실제 rule은 없다. shared Grafana 정본과 lint만 확장하며 ADR-0019의 식 고정 원칙을 따른다. 새 인프라/외부 채널/정책 없음. 공유 관측 설정을 변경하므로 M.

## 작업 항목
- [x] P1. product-service/cache별 get 10m, evict 0s alert와 구분 signal/operation 라벨 추가.
- [x] P2. 정적 식/시간/임계/라벨/instant 계약 및 16개 음성 변이 검증.
- [ ] P3. runbook 경로 갱신과 전체 CI·독립 검증·root 병합·기록.

## 검증 방법
실제 promtool syntax와 기존 PromQL lint 실행. 두 규칙 각각 삭제/시간/임계/operation/서비스/cache grouping/signal/instant 변이를 주입해 거절 확인. 실제 Grafana 발화·해소는 별도 D-063에서 원래 for를 유지해 시험한다. 즉시는 다음 평가주기에서 pending 없이 평가한다는 뜻이다.

## 미해결
D-063이 실제 series 평가를 담당한다. Slack/PagerDuty 전송·GKE배포는 범위 밖. CI/독립 검증/병합 전에는 완료 표기하지 않는다.
