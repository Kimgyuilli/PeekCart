# D-097: 실제 앱 런타임 프로젝트 산출물의 global FQCN 검사

## 1. 명제

같은 앱의 실제 main runtimeClasspath에 없는 모듈 때문에 중복을 오탐하거나,
gateway 또는 전이·runtimeOnly 프로젝트 의존의 global 중복을 놓친다면 미완이다.

| 현재 코드 전제 | 확인 결과 |
|---|---|
| root assertNoDuplicateGlobalFqcn | 고정 commonDeps 네 모듈을 root와 모든 *-service 앱에 붙이고 gateway를 제외한다. |
| user-service | messaging 의존이 없지만 고정 검사 목록에는 들어간다. |
| gateway | observability를 implementation으로 의존하지만 앱 검사 목록에서 빠진다. |
| Gradle 8.14.4 API | 로컬 배포본 javap로 ArtifactCollection.artifactFiles/artifacts 및 ProjectComponentIdentifier.projectPath를 확인했다. 프로젝트 컴포넌트 artifact view로 선택된 내부 산출물과 빌드 의존을 얻는다. |
| 소비자 | root check와 ci-test-matrix-lint의 guard 로그 검사에서 태스크 이름과 : OK를 소비한다. 이름과 출력 접두사는 유지한다. |

등급 M: 공유 빌드 가드 계약 변경이다. 서비스 코드·프로젝트 의존·모듈 경계는 바꾸지 않는다.
ADR-0014의 같은 앱 내 global 중복 금지를 현재 앱 구성에 맞게 검사하므로 새 ADR은 불필요하다.

## 2. 작업 항목

- [x] P1. 활성화된 bootJar가 있는 서브프로젝트를 앱으로 식별하고 앱 main 출력과 실제 runtimeClasspath에서 선택된 프로젝트 artifact만 검사한다.
- [x] P2. 내부 artifact 생성 태스크를 가드 의존에 연결하고 main 출력 디렉터리 및 내부 jar의 global 클래스를 읽는다. 태스크 이름·JwtProvider 금지·OK 접두사는 유지한다.
- [x] P3. 격리된 전체 저장소 복사본에서 실제 Java 컴파일을 거쳐 baseline, messaging 비의존 user의 동명 클래스, runtimeOnly/전이 의존 도입, gateway 중복과 복원 검증을 자동화한다.
- [x] P4. 실제 컴파일 변이와 관련 lint 결과 및 전체 CI 대기 상태를 audit에 기록하고 draft PR을 준비한다. 동일 SHA 전체 CI의 test/guards/images/e2e를 완료 전에 확인한다.

## 3. 검증 방법

| 항목 | 실패 주입과 기대 상태 |
|---|---|
| P1/P2 | assertNoDuplicateGlobalFqcn 정상 통과. user에 OutboxRecordKind를 컴파일해도 messaging이 runtime에 없으면 통과한다. runtimeOnly messaging을 추가하면 user와 messaging의 중복 FQCN으로 실패한다. |
| P2/P3 | gateway에 CommitAwareMetrics를 컴파일하면 gateway와 observability의 중복으로 실패한다. 직접 의존 대신 내부 모듈을 통한 전이 의존으로 바꿔도 실패한다. |
| P3 | user의 messaging compileOnly 의존은 runtime 검사에 들어오지 않는다. 각 실패는 Java 컴파일 완료와 지정 FQCN/모듈을 포함한 가드 진단으로 확인하며, 소스 복원 뒤 정상 통과한다. |
| P4 | ci-test-matrix-lint.sh 정상 및 self-test, git diff 검사, consistency 검사. 전체 Gradle test는 동일 SHA PR CI로 검증한다. |

## 미해결

- 검사 범위는 com/peekcart/global/**와 선택된 프로젝트 artifact다. 외부 jar 및 global 밖 패키지 중복을 보장하지 않는다.
- 루트는 비활성 bootJar의 aggregator이므로 앱에서 제외한다. 앱별 runtime 구성 자체를 바꾸지 않는다.
- mutation self-test는 가벼운 lint가 아니라 실제 컴파일 검사다. CI wiring은 다른 작업자가 소유하므로 이번 변경에서는 workflow를 편집하지 않는다.
- TASKS/progress/ADR 인덱스는 root가 관리한다. 별도 Codex 리뷰 미호출.
