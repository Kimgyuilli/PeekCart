# D-084 — 보호 승인 수동 복구

## 상태와 범위

설계 중. ADR-0040 예약. root 승인 범위는 서버 직접 PG 조회의 확정 결과에 따른 복구, signed ADMIN principal 승인/실행 분리, 감사 및 historical FAILED 경합 안전성이다. 영구 404의 PG 발급 외부 증빙 신뢰 형식은 외부 증빙 미확보로 보류다. 사용자는 이 제한을 유지하는 권장안을 승인했다. 업로드 파일의 해시는 진위 증명이 아니며, 404를 무과금으로 간주하지 않는다. 실 PG·운영 실행은 금지한다.

## 코드로 확인한 전제

- ADR-0035: protected approval(`dispatch_deadline != null`) 수동 인계는 UNRESOLVED를 유지한다. 과거 FAILED/MANUALLY_RESOLVED는 별도 복구가 필요하다.
- PaymentApprovalService.finalizeApproval은 row lock/generation을 검증하고 terminal을 no-op 처리한다. historical FAILED는 이 경로로 회복되지 않는다.
- ApprovalExecutor.verify는 PG 재승인 없이 조회만 하지만 PARTIAL_CANCELED도 failed로 분류한다. 부분 취소는 잔여 과금이 있으므로 신규 복구의 무과금 근거가 될 수 없다.
- TossPaymentSnapshot은 status/canceledAmount/rawResponse만 제공한다. 주문·금액·paymentKey 일치와 잔여 과금 판정은 추가 검증이 필요하다.
- signed internal principal 역할은 USER/ADMIN이다. resolvedBy 요청값만으로 인증하지 않는다. 승인자·실행자 ADMIN ID allowlist를 서로 겹치지 않게 구성하는 안을 검토한다.
- product reservation 해제는 CAS로 재고 한 번 복구를 보장한다. payment의 product 직접 DB 조회는 서비스 경계를 위반하므로 예약 대사 조회 계약이 필요하다.

## 작업

- [ ] P1. 신뢰 증빙·예약/환불 대사 계약 및 ADR-0040 확정. 영구 404는 별도 열린 조건 유지.
- [ ] P2. 증빙 snapshot, 승인/실행 분리, 불변 감사 원장 및 migration 구현.
- [ ] P3. generation/상태 CAS로 historical FAILED와 UNRESOLVED를 안전하게 복구하고 중복 outbox/재고 복원을 차단.
- [ ] P4. HTTP 인증·권한 반례, PG 모순/부분취소/404 반례, 실제 DB 경합과 product 중복 소비를 검증.
- [ ] P5. 필수 CI·독립 검증 후 root 병합/기록.

## 부정 완료 조건

시간 경과, 404, 운영자 주장, 원문 해시만으로 무과금을 확정하거나, 승인자와 실행자가 같거나, 오래된 generation이 terminal을 덮거나, 중복 이벤트로 재고가 두 번 증가하면 미완료다. 서버 조회 복구만 끝나도 영구 404 증빙 경로까지 완료했다고 기록하지 않는다.

## 검증

서명 principal 없는 요청/USER/allowlist 밖 ADMIN/동일 승인 실행자 거부. 조회 결과의 key/order/amount 불일치, PARTIAL_CANCELED/잔여 balance/404/5xx는 상태·outbox 변경 없음. 실제 MySQL에서 reconciler와 실행 경합, historical FAILED, generation 증가 후 stale 승인, 중복 실행 및 중복 소비의 재고 증가 정확히 한 번을 확인한다. 무료 CI 전체 모듈 build/test/root guards와 독립 PR 검증을 최종 gate로 사용한다. 모든 로컬 heavy는 root 슬롯 승인 후 실행한다.
