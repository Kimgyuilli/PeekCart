# D-116 — Phase 5 마감 정리: 문서·계획서·측정 산출물 재구성

기준: 2026-10-26, main `91cfa1f`. 이 문서는 D-116 의 상위 계획이다. 실제 변경은 PR 마다 하위 계획 `D-116-<이름>` 으로 나눠 `/plan → /work → /ship` 을 따로 돈다. 하위 PR 이 머지되면 다음 세션의 `/sync` 가 그 하위 계획을 아카이브하고 §3 표의 상자를 채운 뒤 다음 하위 계획으로 넘어간다. 그 갱신은 다음 하위 PR 의 첫 커밋에 들어간다.

frontmatter 의 `archive: hold` 는 마지막 하위 PR 까지 이 문서를 루트에 붙잡아 둔다. P5 에서 지우고 결과 절에 PR 을 적는다. 그 전까지 이 문서와 audit 에는 PR URL 을 적지 않는다. `plans-archive.sh` 가 URL 의 번호를 이 계획의 PR 로 세기 때문이다. 선례 PR 은 `#133` 처럼 번호만 쓴다.

## 1. 명제

다음 중 하나라도 성립하면 미완이다.

1. 정리 뒤에 Phase 5 의 맥락·판단·근거·성과·결과 가운데 저장소에서 찾아갈 수 없게 된 것이 있다. 지운 추적 파일은 경로와 base 커밋이 기록돼 `git show` 로 되살릴 수 있어야 한다. 추적되지 않던 로컬 파일은 지우기 전에 대체물이 추적돼 있어야 한다. 옮긴 `docs/**/*.md` 는 보존 manifest 로 모든 줄이 정확히 한 번 배정돼야 하고, manifest 로 선언할 수 없는 이동(`docs/` 밖 Markdown, 한 파일 안 재정렬)은 줄 다중집합 대조로 같은 보장을 낸다.
2. `loadtest/reports/` 에 이번 지표를 다시 읽는 데 쓰이지 않는 대용량 원자료가 남아 있다. 워밍업·무효 run 의 지연 TSV, k6 요약 안의 JWT, 무효 관찰 블록의 캡처와 파티션별 lag export 가 그것이다.
3. 문서 구조가 2026-10-26 결정(§2.1)과 다르다. 증적 루트가 셋이거나, 어느 맵에도 없는 문서가 있거나, Layer 1 이 Phase 3~4 기준으로 남았거나, Phase 5 가 열린 채다.
4. 하네스·CI 가 경로를 문자열로 읽는 앵커 7곳(`docs/TASKS.md`, `docs/progress/TASKS-done.md`, `docs/progress/PHASE{N}.md`, `docs/progress/TASKS-archive-*.md`, `docs/plans/` 루트, `docs/plans/done/`, `docs/adr/`)과 `docs/preservation/` 가운데 하나라도 위치나 형식이 바뀌었다.

등급 L: 문서·스크립트·CI·하네스 커맨드에 걸친 구조 변경이고, 되돌리려면 경로를 참조하는 파일을 같이 고쳐야 한다. 하위 계획은 각자 등급을 다시 판정한다.

### 2.3 조사 보고서 정정

- 레인 B·D 와 통합본은 "추적된 모든 `*.md` 는 manifest 없이 삭제·이동할 수 없다" 고 적었다. 실제 검사는 `docs/` 아래 `.md` 만 본다(§2.2 첫 행). 이 작업의 처리 규칙은 바뀌지 않는다. `docs/` 밖 Markdown 도 지우지 않고 옮길 때 줄 대조를 하기 때문이다.
- 통합본 §4 초안은 기존 측정 날짜 폴더를 `summary/`·`raw/`·`grafana/` 로 다시 나누자고 했다. 하지 않는다. 남는 파일을 옮기면 TASKS 행·보호 이력·ADR 이 가리키는 경로가 깨지고, 그중 보호 문서와 완료 행의 링크는 고칠 수 없다. 날짜 폴더에는 집계 파일과 정리 기록만 더한다.
- 통합본 1-3 은 kafka-lag export 2.79MB 전체를 범위 표에 넣었다. 결정 문구는 "무효 run·워밍업·관찰 블록" 이므로 측정 run 의 lag export(10-24 4개, 10-26 3개)는 지우지 않는다. 지우는 것은 10-25 S3 관찰 블록의 `s1`·`w3`·`w4`·`w5` 4개다. `w6` 는 인용된 run 이라 남긴다.

### 2.4 PLAN-BLINDSPOTS 점검

- B1 역의존 스윕: 하위 계획마다 옮기거나 지우는 경로의 인바운드(링크·문자열·테스트·스크립트)를 뽑아 한 줄씩 처분을 적는다. 이 문서는 PR 별 대상 경로와 알려진 인바운드만 적는다(§3).
- B1b 문자열 결합: 경로가 링크가 아니라 문자열로 박힌 곳이 핵심이다. `ci.yml`, 셀프테스트 기대값, `ci-docs-only.sh` 분류 규칙, `check-mutants.py` 의 소스 문자열 anchor, 커맨드 지시문이 그렇다. P2 하위 계획에서 `git grep -F` 로 전수를 뽑는다.
- B2 ADR 과 코드: Layer 1 재작성(P4)은 서술마다 현재 코드로 확인한다. ADR 이 목표로 적은 것을 현재 상태로 옮겨 적지 않는다.
- B4 구체 메커니즘: 하위 계획은 정확한 경로·명령·manifest 이름을 적는다.
- B11 grep false-green: "참조 0" 검사는 전체 경로, 날짜 폴더 기준 상대 경로, Markdown 링크 해석 결과를 모두 본다. 검사가 실제로 잡는지는 가짜 참조를 넣어 먼저 확인한다.
- B3·B5~B10·B12·B13: 해당 없음. 코드 모듈, 런타임 빈, 이벤트, 측정 경로를 바꾸지 않는다.

## 4. 검증 방법

PR 마다 공통으로 한다.

1. 보존: `python3 -B scripts/docs-preservation-ci.py --base <PR-base>` PASS. manifest 를 새로 쓴 PR 은 destination 의 줄 하나를 일부러 빼고 돌려 FAIL 이 나는지 먼저 본다.
2. 하네스: `bash scripts/harness-context.sh --check --base <PR-base>` 가 ok 여야 하고 다이제스트의 단계·열린 행·계획서 수가 예상대로 바뀌어야 한다. `bash scripts/plans-index.sh --check` 도 통과해야 한다.
3. CI lint 잡 명령을 로컬에서 전부 돌린다. 경로를 바꾼 스크립트는 그 셀프테스트도 돌린다.
4. 복원 가능성: 지운 추적 파일마다 `pruned.tsv` 의 blob 이 `git rev-parse <base>:<경로>` 와 같아야 한다. blob 한 글자를 바꾸면 검사가 실패하는지 먼저 본다.
5. 참조 0: 추적 파일 전체에서 지운 경로를 찾는다. 전체 경로, 날짜 폴더 기준 상대 경로, Markdown 링크 해석을 다 본다. 결과는 0건이어야 한다. 정리 기록과 정리 전 인벤토리는 예외다. 가짜 링크를 하나 넣어 검사가 잡는지 먼저 본다.
6. manifest 로 선언하지 못하는 이동(P4 `loadtest/README.md`, P5 PHASE5 재정렬)은 이동 전후 줄 다중집합이 같아야 한다. 헤딩 대응표로 바꾼 줄은 예외로 둔다. 줄 하나를 빼고 돌리면 실패하는지 본다.
7. 앵커 고정: `git diff --name-status <base>` 에 앵커 7곳과 `docs/preservation/` 기존 파일의 이동·삭제가 0건이어야 한다.
