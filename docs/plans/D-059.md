# D-059 — 환불 처리 중 응답의 재시도 분류

## 명제
Toss 취소의 `409 IDEMPOTENT_REQUEST_PROCESSING` 때문에 환불이 FAILED로 종결되거나, 재시도 소진 후 조회로 성공을 확정할 수 없으면 미완이다.

## 코드 검증 및 결정
`TossPaymentClient.toOutcome`은 현재 ALREADY_CANCELED 외 4xx를 영구 실패로 분류한다. `RefundExecutor`는 TRANSIENT를 같은 키로 최대 3회 재시도하고 소진 시 UNRESOLVED를 반환한다. 기존 원장 서비스는 UNRESOLVED를 reconciliation 대상으로 보존한다. payment 단일 모듈, API·이벤트·DB·설정 무변경, 롤백 국소이므로 S. ADR-0018 D3/D5의 결과 불명 처리에 맞추는 분류 수정이며 새 ADR은 불필요하다.
Toss 공식 근거: https://docs.tosspayments.com/reference/using-api/authorization (2026-10-14 확인). 처리 중인 멱등 요청의 409 응답은 재요청 대상으로 안내한다.

## 작업 항목
- [x] P1. 취소 응답의 HTTP 409와 IDEMPOTENT_REQUEST_PROCESSING 조합만 TRANSIENT로 분류한다. 일반 409와 기존 ALREADY_CANCELED 처리는 유지한다.
- [x] P2. 실제 클라이언트와 HTTP 모사 서버를 연결해 타임아웃 뒤 처리 중 응답, 재시도 성공, 소진 및 조회 복구를 검증한다. 원장 통합 테스트로 UNRESOLVED·회신 없음에서 SUCCEEDED·회신 1건으로의 전이를 검증한다.

## 검증
- 분류 테스트: 409+처리 중 코드의 TRANSIENT 및 원문 보존. 다른 409 코드·빈 본문·다른 HTTP 상태는 기존 실패 분류. 409+ALREADY_CANCELED는 조회 분류 유지.
- 호출 경로: 타임아웃 → 409 → 성공은 3회 동일 키로 SUCCEEDED. 타임아웃 → 409 → 409는 3회 후 UNRESOLVED. 이후 조회 전액 취소는 추가 POST 없이 SUCCEEDED.
- DB 경로: 동일 HTTP 실패 시퀀스의 결과를 원장 서비스에 반영해 UNRESOLVED, 결제 APPROVED, outbox 0건 및 reconciliation 후보를 확인. 조회 확정 후 원장 SUCCEEDED, 결제 REFUNDED, outbox SUCCEEDED 1건 확인.
- 수정 전 회귀 테스트 실패 확인 후 수정하여 통과 확인. ./gradlew test 및 관련 integration-test-container-lint 실행.

## 미해결
실 Toss 호출과 지연 발생 빈도는 D-064 범위다. 승인 분류와 다른 PG 오류 코드는 이번 취소 경로 수정 범위 밖이다. 부채 등록 PR #173을 선행 브랜치로 연결하고, D-059 PR 생성 후 완료 기록을 갱신한다.
