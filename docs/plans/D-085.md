# D-085: CI gate 실패 전파 의미 검사

## 1. 명제

선행 job 하나라도 실패·skip·취소됐는데 취소되지 않은 gate의 전파 스텝이 실행되지 않거나,
전파 스텝 실패를 무시하는 설정을 lint가 허용한다면 미완이다.

| 코드 검증 전제 | 확인 결과 |
|---|---|
| `scripts/ci-release-gate-lint.sh` | CRG-003은 5개 비교 문자열과 `!cancelled()` 존재만 확인한다. `&&` 결합을 구별하지 않는다. |
| `continue-on-error` 검사 | gate/e2e/publish job만 검사하며 전파 스텝은 검사하지 않는다. |
| `.github/workflows/ci.yml` | 현재 전파 조건은 `!cancelled() && (5개 비성공 비교의 OR)`이고 `exit 1`로 끝난다. |
| ADR-0030 | 필수 5개 job의 실패·skip 전파와 취소 시 미실행이 기존 결정이다. 새 ADR은 필요 없다. |

등급 M: 공유 CI 정책 검증 표면을 변경한다. 서비스 모듈·API·인프라 변경은 없고 되돌림은 linter에 국한된다.

## 2. 작업 항목

- [x] P1. 조건식의 제한 문법을 파싱하고 5개 결과의 4가지 상태와 취소 여부 전체 조합을 기존 계약과 대조한다. 알 수 없는 문법은 실패로 처리한다.
- [x] P2. 전파 스텝의 `continue-on-error`를 미선언 또는 불리언 `false`로 제한한다.
- [x] P3. 정상 표현식 대안과 `&&`·step 오류 무시·실패/skip/취소 누락·괄호/문법 오류 변이를 self-test에 추가한다.
- [x] P4. 관련 lint 결과와 전체 CI/별도 리뷰의 대기 상태를 audit에 기록하고 draft PR을 준비한다. 완료 전에는 동일 SHA의 전체 CI를 확인한다.

## 3. 검증 방법

| 항목 | 검증 |
|---|---|
| P1 | 실제 workflow baseline과 동치식은 통과하며 각 upstream의 failure/skipped/cancelled를 고립한 조건 누락은 CRG-003으로 실패한다. 4^5 × 2 = 2,048개 조합을 대조한다. |
| P2 | step `continue-on-error: true` 및 동적 표현식은 실패하고 명시적 `false`는 통과한다. |
| P3 | OR를 AND로 바꾼 실제 조건·혼합 연산자·상시 true/false·알 수 없는 함수/토큰·불균형 괄호를 주입해 검출한다. 원본 24개 변이도 유지한다. |
| P4 | `bash -n scripts/ci-release-gate-lint.sh`, 정상 실행, `--self-test`, 관련 CI lint 및 전체 PR CI를 확인한다. 로컬 Gradle/Docker는 동시 실행 슬롯을 차지하지 않고 GitHub Actions에서 실행한다. |

## 미해결

- GitHub Actions 식 전체·run 셸 본문 의미 분석은 범위 밖이다. 제한 문법 밖의 조건식은 명시적으로 거부하며 셸 검사는 기존 계약을 유지한다.
- TASKS/progress/ADR 인덱스 완료 갱신은 병렬 작업 충돌을 피하도록 root가 담당한다.
- 별도 Codex 리뷰 미호출. root가 지정하는 독립 검토는 실제 결과와 대상 SHA를 별도로 기록한다.
