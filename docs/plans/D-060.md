# D-060 — 승인과 예약 lease 회수 사이의 fence

## 1. 명제
재고 회수가 이긴 주문에 PG 승인이 시작되거나, 승인 결과 불명 중 재고가 회수·재판매되면 미완이다. crash/회신 역전으로 보호된 재고가 조용히 유실되어도 미완이다.

## 2. 배경

| 코드 검증 | 사실/처분 |
|---|---|
| PaymentCommandService | T1 직후 PG 호출, Product 확인 없음 → 비동기 접수 |
| PaymentApprovalService / JpaRepository | CLAIMED부터 시작, reconcile은 조회 전용 → WAITING_STOCK/READY 및 deadline 추가, 조회 전용 유지 |
| StockReservationJpaRepository | release와 confirm 모두 RESERVED CAS → HELD 획득과 확정 결과별 해제 추가 |
| StockReleaseConsumer | order.cancelled와 payment.failed가 같은 release 호출 → 해제 권한 분리 |
| StockReservationService.recordRefundResult | marker만 기록 → fenced 예약의 성공 환불 재고 복구 추가 |
| PaymentEventConsumer / OrderEventConsumer | 승인-취소 경합의 자동 환불 존재 → 유지, 실패 회신은 CANCELLED에도 발행 |
| DlqTopology / ReplayPolicyRegistry | 문자열 기반 구독/발행 계약 → 새 result 및 Product payment.requested 구독 함께 갱신 |

Payment/Product/common, 공개 API·이벤트·DB가 바뀌므로 L. ADR-0034 선행 작성. 사용자 선택: 비동기 접수 후 조회.

블라인드스팟: B1/B1b API confirm 호출자·테스트·E2E 및 topic/group 식별자를 함께 수정한다. 클래스/모듈 이동 없음. B2 현재 원장·outbox·환불 사용. B3/B5 공유 DTO는 common, 스키마는 서비스 소유. B4 CAS와 DB 커밋 뒤 dispatcher로 구체화. B6/B8 새 서비스/공유 빈 없음. B7 bulk UPDATE의 flush/clear 경계 확인. B9 늦은 허가/실패/환불/completed 역전 검증. B10 서비스별 Flyway 활성 통합테스트. B11 신규 문자열 리터럴 계약 lint. B12 실제 Product CAS와 release 경합 및 PG 정지 구간의 회수 시도를 검증한다.

## 검증 방법
- V1 Product: 회수가 먼저면 허가 false; HELD가 먼저면 lease를 과거로 밀고 sweeper/order.cancelled를 실행해도 가용 재고 불변. 다중 thread CAS 경합은 한쪽만 이긴다.
- V2 Product: payment.failed 및 환불 SUCCEEDED는 재고 정확히 1회 복구. 환불 FAILED는 유지. completed와 성공 환불의 양 순서에서 재고/marker 정합. Outbox 실패 주입 시 HELD와 회신 함께 rollback.
- V3 Payment: API 202 이후 PG 0회, 결과 수신 전 dispatch PG 0회. READY만 1회 claim. 거절/만료/취소에는 PG 0회와 실패 Outbox. 늦은 허가/중복 dispatch는 재승인 불가.
- V4 Payment: PG 호출 중 취소/claim 회수/프로세스 경계 실패를 주입해 기존 조회 확정과 환불 원장 보존. CLAIMED 이전 단계는 reconcile 대상 아님.
- V5 실제 스택 Saga의 승인 실패 체인에 HELD 획득 결과와 stub 호출 순서 증거 추가. API E2E 기대값을 202로 갱신. 가능한 로컬 실행 환경을 확인하고 미실행이면 명시.
- V6 `./gradlew test`, integration-test-container, kafka-subscription-contract, saga-contract-matrix, scheduler-lock-contract, migration-grant lint 및 diff whitespace.

## 미해결/범위 밖
실 PG 검증은 D-064, 전체 환불 E2E 확대는 D-061. 사용자 취소와 승인 시작의 동시 발생 자체는 기존 자동 환불로 수렴하며 D-060은 그 사이 재고 재판매를 차단한다. 운영 배포/롤백은 ADR 절차만 제공한다. 과금 불명 상태의 강제 재고 반환은 추가하지 않는다.
