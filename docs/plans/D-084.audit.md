## 관측 경계와 독립 읽기 검토 보완

- recovery branch의 정본 alert HEAD↔working 구조 비교: 바뀐 rule은 `peekcart-payment-approval-stale` 한 개다. 기존 D-063 compensation/DLQ/outbox rule 전체는 동일하다. 이 base에는 D-070 cache 두 rule이 없으므로 최종 통합 뒤 D-063 대상 다섯 rule 동일성을 다시 확인해야 한다.
- `recovery_pending`을 빼는 음성 반례를 추가해 recovery branch PromQL self-test 29종 PASS. monitoring worktree c406204/run2 source hash는 변경하지 않았다. run2를 새 approval recovery 상태 경보의 실제 평가 증거로 확장하지 않는다.
- 독립 검증자의 초안 지적: strict DONE 확인 후 두 번째 일반 조회가 부정 결과를 실패 해제로 바꾸는 경로 제거. 검증한 DONE 원문만 성공/고아 환불에 사용한다. valid DONE 다음 다른 주문 ABORTED가 준비돼도 조회 1회로 끝나는 회귀를 추가했다(실행 대기).
- 요청 응답 유실은 동일 주문 요청으로 기존 id 회수. 실행 진행/완료 중복은 같은 결과와 감사만 반환. 유효 principal의 거절은 업무 rollback과 분리된 REQUIRES_NEW 감사 행으로 보존한다.
- root 승인 재개 계약: 명시 false 응답 뒤에만 fresh PG→새 generation→새 snapshot→재승인. 미응답은 fresh PG의 같은 확정 부정일 때 동일 id/generation/version 실행만 명시적으로 재전달한다. DONE/불명/모순이면 보호 유지. 일반 DLQ replay DENY는 그대로다.
- 실제 DB 테스트 준비: historical FAILED, 두 실행자 경합 한 outbox, stale generation, 늦은 DONE→고아 환불, 거절감사, false 응답 재개와 옛 generation 거절, 응답유실 재전송, Product stale version/중복·동시 재고 한 번. HTTP 서명/역할/allowlist 분리 반례도 준비했다. 현재 실행 전이므로 통과/완료 표시하지 않는다.
