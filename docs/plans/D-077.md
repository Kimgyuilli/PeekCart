# D-077 — 현재 재고 동시성과 비동기 취소 설명

## 명제
현재 문서가 재고 Redis 락을 사용한다고 하거나 취소 응답이 재고 복구 완료를 보장한다고 읽히면 미완이다.

## 배경과 ADR 판단
단일 Order 모듈의 설명과 Layer 1 문서만 정정한다. 실행 계약·스키마·의존성 변경 없음, 되돌림 국소이므로 S이며 새 ADR은 불필요하다. Inventory.@Version, StockReservationConsumer의 트랜잭션, ProductKafkaConfig의 jitter 3회, OrderCommandService의 취소 Outbox와 StockReleaseConsumer를 직접 대조했다. ADR-0025 결정을 따른다.

## 작업 항목
- [x] P1. Layer 1 설계 §9-1 및 요구사항 §7-2에서 분산 락·재고 부족·오버셀링 단정과 Facade 경계 설명을 현재 낙관락·재시도·DLQ 계약으로 정정.
- [x] P2. 주문 취소 swagger와 application javadoc을 비동기 예약 해제에 맞추고 응답 시 복구 미보장을 명시.
- [ ] P3. 최신 head의 전체 CI gate와 독립 PR 검증 후 root 병합·기록.

## 검증
기존 §9-1의 Redis 직렬화/즉시 재고 부족/Facade 문장을 반례로 대조해 제거를 확인한다. Inventory/소비자/취소 Outbox/error handler 소스와 새 설명을 대조한다. 실행 코드 변경이 없어 설명을 복제하는 테스트는 추가하지 않는다. git diff --check와 문서 lint를 수행하고, 사용자 승인에 따라 전체 모듈 build/test·root guards·필수 gate는 CI 증적으로 대체한다.

## 미해결
D-073 역사적 측정 정정은 별도 작업이다. CI·독립 검증·병합 전까지 부채 완료가 아니다. root만 TASKS/PHASE/index를 갱신한다.
