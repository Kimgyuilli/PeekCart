# D-105: ship 재개 조회 실패 구분

## 1. 명제
원격 조회가 실패했는데 Step 6(push) 또는 Step 7(PR 생성)을 반환하거나, 조회에 성공한 부재 결과까지 차단하면 미완이다.

### 코드로 확인한 배경
| 전제 | 확인 결과 |
|---|---|
| `.claude/scripts/lib/ship.sh` | `git ls-remote`, `gh pr list`의 exit와 stderr를 버리고 stdout 공백만 검사한다. |
| `.claude/commands/ship.md` 재진입 | helper의 숫자 0/3/6/7/8 결과를 절차로 안내한다. 새 미확정 결과와 중단 규칙이 필요하다. |
| 호출 경계 | 자동 실행 소비자는 없고 ship 커맨드 문서가 소비한다. branch/status 실패와 detached HEAD도 원격 조회 전에 차단해야 한다. |
| 테스트/CI | Bats 회귀는 로컬 전용이며 CI에 미연동이다. 새 검사는 독립 shell self-test로 lint job에서 실행한다. |

등급 M: 공유 helper의 결과 계약에 `unknown`/exit 1을 추가한다. 단일 하네스 범위이며 되돌림은 이 변경 안에서 끝난다. 새 외부 의존성·아키텍처 경계·인프라가 없어 ADR은 추가하지 않는다.

## 2. 작업 항목
- [x] P1. 성공한 조회의 부재와 조회 실패를 구분하고, 실패 시 `unknown`/exit 1과 실패 명령·종료 코드·원인 stderr를 남긴다. 로컬 사실 조회 실패/빈 브랜치도 중단한다.
- [x] P2. 정상 Step 3/6/7/8/0과 원격 실패(빈/부분 stdout, stderr 없음 포함), 로컬 실패를 격리된 실행 파일 대역으로 검증하고 CI에 연결한다.
- [x] P3. 재진입 문서의 계약·중단 규칙을 갱신하고 실제 검증/미충족 상태를 audit에 기록한다.

## 3. 검증 방법
- P1/P2: Git/gh 대역의 stdout, stderr, exit를 독립 주입한다. 성공+공백은 Step 6/7, 실패+공백/부분 출력은 `unknown`/exit 1이어야 한다. 원인 stderr와 실패 명령·exit를 확인하고 호출 기록으로 실패 뒤의 조회가 없음을 확인한다. 정상 dirty/완료 링크 양쪽 파일도 대조한다.
- P2: 기존 구현을 같은 검사에 넣으면 원격 실패 케이스가 실패해야 한다. `bash scripts/ship-resume-selftest.sh`, 기존 Bats 전체, `bash -n`을 실행한다.
- P3: ship preflight, consistency precheck, writing lint를 실행한다. 전체 `./gradlew test`는 공유 자원 슬롯을 조정한 뒤 실행하거나 GitHub Actions의 전체 테스트 shard로 확인한다. 전체 CI는 필수이며 pending을 통과로 기록하지 않는다.

## 미해결 / 범위 밖
- root가 TASKS·PHASE5·ADR index·총괄 계획의 완료 문서를 소유한다. 이 브랜치에서는 변경하지 않고 실제 PR과 검증 결과를 전달한다.
- 원격 브랜치의 HEAD 동기화·closed PR 복구·네트워크 재시도 정책은 이 작업의 조회 실패/부재 구분 범위 밖이다.
