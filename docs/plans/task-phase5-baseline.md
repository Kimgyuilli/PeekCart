# task-phase5-baseline

Phase 4 가 종결([#133](https://github.com/Kimgyuilli/PeakCart/pull/133))되면서 `docs/07-roadmap-portfolio.md §16`
의 사전 로드맵이 소진됐다. Phase 5 는 순서표를 다시 만들지 않고 **필요하다고 판단한
시점에 항목을 추가하는 방식**으로 간다. 그런데 문서 여러 곳이 "순서표가 있다"를 전제로
쓰여 있었다.

코드 변경 0. 문서 기반 세팅이다.

## 명제

로드맵 없이 가기로 했으면, **로드맵을 전제하던 문서 구조를 먼저 걷어내야 한다.**
`## 현재 단계` 가 종결된 Phase 4 를 가리키고 있으면 다이제스트가 잘못된 현황을 보고하고,
`§16` 에 Phase 5 작업 목록을 적으면 그 순간 그게 로드맵이 된다.

## 결정

**1. 추적 축을 D- 하나로 통합했다.**

Phase 4 까지는 로드맵 순서표 + D- 부채표 2축이었다. Phase 5 는 순서표가 없으므로 축이
하나 남는다. 여기서 "부채 해소"와 "새로 하고 싶은 것"을 별도 표로 나눌 수도 있었지만
나누지 않았다 — 수요 기반에서는 둘 다 *지금 필요하다고 판단한 작업* 이라는 같은 성격이고,
표가 둘이면 항목을 추가할 때마다 **어느 쪽에 적을지부터 정해야 해서** 추가 비용이 생긴다.
로드맵 없는 방식의 이점이 "생각나면 바로 적는다"인데 그 앞에 분류 단계를 두면 상충한다.

부수 효과로 `scripts/harness-context.sh` 변경이 0이다. 파서가 이미 이 표를 읽는다.

**2. `§16` 에 Phase 5 작업 목록과 Exit Criteria 를 적지 않았다.**

Phase 1~4 는 각각 작업표 + Exit Criteria 를 가졌다. Phase 5 에 같은 형식을 채우면
그게 로드맵이다. 대신 "사전 순서표가 없는 단계"라는 사실과 현황 문서 포인터만 적었다.

**3. 항목 추가 규칙에 동기 기록을 명시했다.**

로드맵이 사라지면서 **근거를 붙들어 주던 축이 같이 사라진다.** Phase 4 까지는 "순서표
③번 항목"이라는 위치 자체가 왜 하는지를 설명했다. 수요 기반에는 그 위치가 없으므로,
`요약` 에 왜 필요한지 · `묶음` 에 어디서 발견했는지를 적지 않으면 나중에 복원이 안 된다.
Phase 5 에서 유일하게 늘어난 규율이다.
