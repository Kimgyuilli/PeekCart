# D-068 MySQL 패치 버전 고정

## 1. 명제

공용 통합 테스트·Compose·E2E·k8s·실행계획 테스트의 MySQL 패치가 다르거나 부동 태그이면 미완이다.
환경 이미지 설정 계약 변경 하나에 해당하므로 M. 제품 모듈/API/DDL 변경은 없다.

| 코드 전제 | 확인 | 반영 |
|---|---|---|
| SharedContainers와 Compose 2종 및 k8s | mysql:8.0 부동 태그 4곳 | 8.0.46으로 고정 |
| OrderCursorQueryPlanTest | 8.0.46 고정, MySQL만 사용하는 DataJpaTest | 버전 유지, 독립 컨테이너 예외 사유 정정 |
| CI lint | 컨테이너 수명 검사는 있지만 이미지 버전 가드는 없음 | 이미지 5개 선언 고정 검사와 음성 대조군 추가 |

ADR 판단: 새 인프라/경계/의존성 도입 없이 기존 MySQL 8.0의 검증 패치를 맞춘다. 신규 ADR 불필요. 실제 클러스터 배포는 범위 밖이다.

## 2. 작업 항목

- [x] P1. 부동 이미지 4곳을 8.0.46으로 고정하고 독립 MySQL 예외 사유를 수정한다.
- [x] P2. 누락·부동 태그·패치 불일치를 거부하는 CI guard와 self-test를 추가한다.
- [x] P3. 전체 모듈 통합 테스트·OrderCursorQueryPlanTest·E2E·root guard·gate 및 독립 검증으로 검증 후 root가 병합·기록한다.

## 3. 검증 방법

- mysql-image-lint: 실행 이미지 5곳을 독립 기대값과 비교. 각 표면에 8.0/latest/다른 패치/삭제/중복을 주입하면 실패해야 한다.
- 기존 integration-test-container-lint 및 self-test로 예외 규약 보존.
- 무료 CI의 전체 모듈 test로 기존 DATETIME(6)/DDL 계약을 실행하고 OrderCursorQueryPlanTest의 실제 Hibernate SQL EXPLAIN 및 IGNORE INDEX 음성 대조군을 확인한다.
- E2E CI는 동일 고정 MySQL 이미지로 Flyway/서비스 기동·Saga 검증을 실행한다. k8s 배포 성공을 주장하지 않는다.
