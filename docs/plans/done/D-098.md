# D-098: 완료 행·계획 이동 보존 검사

## 1. 명제와 코드 전제

ID 집합이나 줄 집합만 같아서 중복·반복 삭제·순서 변경·문서 소속 변경·상대 링크 오지정을 통과시키거나, 정당한 상태 변경과 역사 정정 추기를 모두 금지하면 미완이다. 광범위 파일 제외로 검증을 우회해도 미완이다.

기준 `a7ffa11`의 done/ship 명령과 skill, plans-archive.sh, CI를 확인했다.

| 전제 | 코드 대조 |
|---|---|
| 완료 행 이동 | done Step6/ship Step8은 상태와 PR 링크를 갱신하고 done 표 아래로 이동하라고 하지만 재사용 보존 검사는 없다. |
| 실제 정정 추기 | TASKS-done 표 아래에는 D-080/D-073 정정 footer가 있다. 행 이동 후에도 이 원문·순서를 보존해야 한다. |
| archive | PR 상태로 후보를 고르고 git mv 및 broad docs/plans 문자열 치환을 수행한다. 파일 본문과 상대 링크 목적지/앵커 보존 검사는 없다. |
| CI | 개별 정책 lint와 archive self-test가 있지만 위 이동 보존을 검증하지 않는다. |
| 기존 한계 | TASKS의 D-098은 D-052/053/055 조사상의 checker 한계를 기록한다. 그 작업들의 실제 원본 누락이 확인됐다는 뜻으로 바꾸지 않는다. |

등급 M: 새 공유 검증 CLI/manifest와 done/archive/CI 소비 계약을 함께 추가한다. 앱 모듈·환경·아키텍처 경계는 바꾸지 않으므로 새 ADR은 불필요하다. D-099의 현행 corpus 건강 검사는 별도 PR로 유지한다.

## 2. 작업 항목

- [x] P1. 명시 base와 현행 tree를 비교하는 보존 검사에서 D-ID 유일성·다중집합, 본문/상태 cell 분리, 남은 행 순서와 done 목적지 append 순서, 기존 footer를 확인한다. 정당한 상태/PR 변경만 구조적으로 허용한다.
- [x] P2. 선언한 source line 구간과 destination parts의 ordered-content mapping으로 분리·병합도 검사한다. 모든 원본 구간은 정확히 한 번 배정하고 각 목적지의 원문 순서를 확인한다. plan/audit 이동은 선언한 source/destination 별로 순서 있는 원문을 비교하고 상대 링크 재작성은 의미상 같은 파일/앵커일 때만 허용한다. 새/변경 local link의 대상·앵커도 검사한다.
- [x] P3. 역사 추기는 기존 원문 이후 append로 허용하고 사실 정정은 이유와 정확한 old/new 범위가 있는 좁은 명시 예외만 허용한다. no-op/중복/미사용/과도 범위 예외는 실패시킨다.
- [x] P4. done/ship/archive 절차와 CI에 정상 및 음성 대조를 연결한다. archive --apply는 명시 선택 목록을 요구한다. D-084와 전체 미완 orchestration을 포함한 전체 후보 자동 이동을 금지한다. archive 후보 판정 및 D-099 corpus 의미는 범위 밖으로 유지한다.
- [x] P5. 실제 정상 source에서 fixture를 만들고 중복 ID/반복 삭제/body 변경/순서/다른 목적지/footer 유실/오류 링크·앵커를 하나씩 주입해 실패를 확인한다. 정당한 status/relative link/append/좁은 정정은 통과해야 한다.

## 3. 검증 방법

운영 명령이나 Gradle/Docker 없이 임시 git fixture를 사용한다. 기존 TASKS/done footer와 반복 문장을 포함한 plan/audit를 원본으로 보존한 뒤 실제 checker CLI와 archive 경로를 실행한다. 정상 이동 결과의 source와 destination 바이트 및 상대 링크 의미를 대조한다. 같은 전역 줄 다중집합을 유지하면서 파일 소속이나 순서만 바꾼 입력도 실패해야 한다.

ID 추가 자체는 새 부채 등록과 혼동하지 않게 명시적인 등록 계약으로 분리하고, 중복은 예외 없이 실패한다. 허용 목록 자체도 검증해 잘못된 경로나 지나치게 넓은 범위가 bypass가 되지 않아야 한다. CLI 오류·검증 위반·정상 결과의 종료 코드를 구분하고 CI가 비정상 결과를 전파하는지 확인한다.

## 미해결과 소유권

TASKS/PHASE/master와 ADR index의 캠페인 완료 편집은 root 소유이므로 변경하지 않는다. 일반 문서 편집 전체를 불변으로 막지 않고 이동 선언 대상 및 보호 아카이브에 계약을 한정한다. root 기록 branch의 보존 요구는 통과 대상으로 제공하되 내용을 임의 삭제·정규화하지 않는다. 실제 문서 이동은 이번 구현을 검증하는 temp fixture 이외에는 수행하지 않는다. D-099/103/104 및 일반 CI 생존성 D-088을 이 PR에 섞지 않는다.

## 독립 검토 후 보완
