# D-057 — `plan.md` · `work.md` 공통 리뷰 규칙의 단일 문서화

## 1. 명제

아래 중 하나라도 성립하면 미완이다.

- `.claude/commands/plan.md` 와 `work.md` 에 Codex 호출 게이트, 결과 처리, 라운드 2 규칙, 리뷰 상태 4값이 거의 같은 문장으로 두 벌 있다. 한쪽만 고치면 규칙이 갈라지고, 두 벌 모두 호출마다 컨텍스트에 실린다
- 공통 규칙을 옮긴 뒤 커맨드 본문만 읽고 진행했을 때 **승인 없는 Codex 호출**이나 **리뷰 실패를 0건으로 접는 보고**가 가능해진다
- 규칙 문장이 옮기는 과정에서 사라지거나, 밖에서 이 두 파일의 절 번호를 가리키는 참조가 가리킬 곳을 잃는다

### 코드 검증 (2026-09-30)

`difflib` 로 두 파일을 맞대면 3줄 이상 동일 블록이 8개, 약 4.1KB다. 가장 큰 것은 §6 결과 처리 53줄(2.3KB)이다. 거의 같은 문장까지 넣으면 §5-0 게이트도 겹친다. work.md 는 이미 "`/plan` §5-0 과 같다", "`/plan` §7 과 같은 닫힌 형태" 로 plan.md 를 가리키는 곳이 있다.

밖의 참조는 절 번호로 이 구획을 가리킨다. `harness-rationale.md` 의 "출처" 줄 12곳, `writing.md:113`(work §9 의 상태 4값), `scripts/codex-review-render.sh:6`(plan §6 의 자동 통과 문장), `ADR-0028:235`(work §8, 이번에 안 건드림)다. D-027 ① 선례대로 커맨드의 절 제목 줄은 그대로 둔다. 규칙 본문이 옮겨가는 `harness-rationale.md` 출처 3종과 `writing.md:113` 은 새 문서를 함께 가리키게 고친다. `codex-review-render.sh` 주석이 인용한 "P0/P1 이 0건이면 자동 통과" 는 plan.md 고유 문장이라 §6 에 남으므로 고치지 않는다(구현 중 정정).

공통 문서는 Codex 를 실제로 부를 때만 읽는다. 게이트가 `blocked` 인 동안에는 호출마다 읽지 않는다. 그래서 공통 문서를 읽지 않아도 지켜져야 하는 두 불변식은 커맨드 본문에 한 줄로 남긴다: (1) 판정이 먼저이고 `allowed` 여도 사용자 승인 없이 부르지 않는다, (2) 렌더러 exit 2 는 `미결` 이며 0건으로 접지 않는다.

ADR 선행 판단: 외부 의존 · 경계 · 인프라 변경이 없다. 머지된 D-053 계획서 아카이브를 같은 PR 에 싣는다.

## 2. 작업 항목

- [x] P2. `plan.md` §5-0 · §6 · §7 · §8 에서 공통 부분을 지우고, 절 제목 아래에 공통 문서 포인터와 커맨드 고유 문장만 남긴다. 두 불변식 한 줄을 §5-0 과 §6 에 둔다
- [x] P3. `work.md` §5-0 · §6 · §7 · §9 를 같은 방식으로 줄인다. "`/plan` §5-0 과 같다", "`/plan` §7 과 같은" 은 공통 문서를 가리키게 바꾼다
- [x] P4. 밖의 참조를 고친다. `harness-rationale.md` 의 출처 줄 중 옮긴 규칙에 해당하는 것(R-plan-3, R-review-1~3, R-plan-4~6, R-work-2·3)에 `codex-review.md` 절을 덧붙이고, `writing.md:113` 을 새 위치로 고친다

## 3. 검증 방법

- **V1 (보존)**: 이동 전 두 커맨드에서 사라진 비어 있지 않은 줄을 개수까지 세어, 이동 후 두 커맨드와 공통 문서의 합에 모자라지 않는지 비교한다. 예외는 다시 쓴 포인터 · 불변식 줄과 "plan.md 쪽을 원문으로" 에서 버린 work.md 변형 문장이며, 목록으로 명시한다. 주입: 공통 문서에서 severity 표 한 줄을 지우면 부족 1건이 잡혀야 한다
- **V2 (절 제목)**: 두 커맨드의 `^#{1,4} ` 헤딩 줄 목록이 이동 전후 같다. 주입: 헤딩 하나를 바꾸면 차이가 잡힌다
- **V3 (불변식)**: 두 커맨드 본문에 "승인 없이 부르지 않는다" 와 "exit 2" · "`미결`" 한 줄이 각각 있다. 공통 문서를 치운 상태에서도 grep 으로 둘 다 나온다
- **V4 (참조)**: `harness-rationale.md` · `writing.md` 가 가리키는 `codex-review.md` 절 제목이 실제로 있다. 주입: 공통 문서의 절 제목 하나를 바꾸면 검사가 잡는다
- **V5 (크기)**: `plan.md` + `work.md` 바이트가 이동 전(29,995B)보다 줄었는지와 그 양을 보고한다
- **V6 (회귀)**: `bats .claude/scripts/tests/bats` 전량 통과(`codex_gate` · `review_health` 는 스크립트를 검사하므로 문서 이동에 영향이 없어야 한다), `scripts/codex-review-render-selftest.sh` 통과
