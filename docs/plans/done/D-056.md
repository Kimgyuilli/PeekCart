# D-056

## 1. 명제

`scripts/scheduler-lock-contract-lint.sh` 나 `scripts/codex-review-render-selftest.sh` 중 하나라도 CI 에서 돌지 않아,
그 스크립트가 잡는 위반을 넣은 PR 이 초록으로 통과하면 미완이다.

코드 검증(2026-09-29):

| 확인 | 결과 |
|---|---|
| 두 스크립트 호출처 | `.github/`·`scripts/` 모두 0건. 자기 자신 외 참조 없음 |
| 로컬 실행 | scheduler lint `OK`(exit 0), render selftest 35 통과 · 0 실패 · 0 건너뜀 |
| 같은 관례의 다른 selftest | `saga-contract-matrix-selftest.sh` 는 `saga-contract-matrix-lint.sh --self-test` 가 exec 로 부른다. 미배선은 D-056 의 두 개뿐 |
| render selftest 의존 | `jq`, `python3` (ubuntu-latest 기본 포함). V9 는 `.cache/codex-reviews` 가 없으면 skip 하고 실패로 세지 않는다 |
| 삭제 대안 | scheduler lint 는 D-024 풀 확대(1 → 4)의 안전 조건이라 삭제하면 불변식이 사라진다. render selftest 는 `/plan`·`/work` 가 쓰는 렌더러의 false-green 방지 장치다. 둘 다 배선으로 판정 |

등급 M 근거: 단일 파일(`ci.yml`) 변경이지만 모든 PR 의 필수 게이트에 검사를 더하므로 파급을 높게 본다.

## 2. 작업 항목

- [x] P1. `ci.yml` lint 잡의 "Run CI policy lints" 단계에 `bash scripts/scheduler-lock-contract-lint.sh` 추가. 막는 불변식을 주석 한 줄로 남긴다
- [x] P2. 같은 단계에 `bash scripts/codex-review-render-selftest.sh` 추가. CI 에서 V9 가 skip 되는 사실을 주석으로 남긴다

범위 밖: scheduler lint 에 `--self-test` 를 새로 만드는 것. 배선 여부가 이 task 이고, lint 가 위반을 잡는지는 아래 검증의 실패 주입으로 확인한다.

## 3. 검증 방법

- P1: 임의 `@Scheduled` 메서드의 `@SchedulerLock` 을 로컬에서 지우고 lint 가 `[SCHED-001]` 로 exit 1 인지 확인한 뒤 원복
- P2: `codex-review-render.sh` 의 빈 응답 판정(exit 2)을 로컬에서 0 으로 바꾸고 selftest 가 실패(exit 1)하는지 확인한 뒤 원복
- 배선: PR CI 의 lint 잡 로그에 두 스크립트의 출력(`[SCHED-LOCK] OK`, `통과 N · 실패 0`)이 찍히는지 확인. 로그에 없으면 배선되지 않은 것으로 본다
