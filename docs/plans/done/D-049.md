# D-049

## 1. 명제

order · payment · product · notification 중 어느 서비스의 `src/main` 에라도 ADR-0033 D1 이 공유로
정한 32개 클래스의 사본이 남아 있으면 미완이다. 공유 모듈을 서비스 하나라도 소비하지 않아
빌드·부팅·통합 테스트가 깨지면 미완이다. `user-service` 의 classpath 에 새 모듈이 들어가도 미완이다.

## 2. 배경

결정은 ADR-0033. 대상은 서비스마다 byte 동일한 32개 파일이다(`global.outbox` 9 · `global.idempotency` 6 ·
`global.deadletter` 16 · `global.config.ShedLockConfig`). 이 파일들을 새 모듈 `peekcart-common-messaging` 으로 옮기고,
서비스마다 달라야 하는 3개(`DeadLetterConsumer` · `DeadLetterQuarantineConsumer` · `LedgerOwnerConfig`)와
Flyway 스키마는 서비스에 남긴다.

### 코드 검증 (2026-09-29)

| 전제 | 확인 방법 | 결과 |
|---|---|---|
| 32개가 4벌 byte 동일 | order 사본 기준 `cmp` | 참. 다른 것은 위 3개와 `OutboxEventStatus` 뿐 |
| `OutboxEventStatus` 차이 | `diff` | order·product 만 `BACKFILL` 보유. payment == notification |
| `BACKFILL` 사용처 | grep | order·product V5 마이그레이션과 그 통합 테스트뿐. payment/notification 의 `status` 는 `VARCHAR(20)` |
| 공유 후보가 서비스 전용 3개나 도메인을 참조하지 않음 | grep (import + 같은 패키지 이름) | 0건. 따로 떼어도 컴파일 가능 |
| 공유 후보의 모듈 밖 의존 | import → 소유 모듈 매핑 | `:common` (kafka·replay·retention·port) + `:peekcart-common-observability` (`CommitAwareMetrics`) + shedlock · spring-security-core |
| 패키지가 서비스 간 동일 | `package` 선언 | 전부 `com.peekcart.global.*`. 이동해도 서비스 쪽 import 변경 0 |
| `user-service` 도 `:common` 의존 | build.gradle | 참. `:common` 편입이 아니라 새 모듈인 이유 (ADR-0033 Alt A) |
| notification 의 ShedLock 자체 사용 | grep (`global/` 밖) | 0건. 공유 코드만 쓴다 → 새 모듈이 `api` 로 노출하면 서비스 선언이 불필요해진다 |

### PLAN-BLINDSPOTS

**B1 역의존 스윕.** FQCN 은 바뀌지 않으므로, 컴파일러가 강제하는 간선은 "모듈 의존 추가"로 전부 해소된다.
문제는 **파일 경로를 문자열로 참조하는** 곳이다.

| 인바운드 | 처분 |
|---|---|
| 서비스 `src/main` 도메인 코드 (order 5 · payment 5 · product 6 · notification 1 파일) | 유지. 모듈 의존 추가로 해소 |
| 서비스 `src/test` 의 `global.*` 통합 테스트 | 유지 (사용자 결정 — 서비스별 배선 검증) |
| order `src/test` 의 `OutboxPollingServiceTest` · `DeadLetterEndpointReplayAuthTest` | **이동** → 새 모듈 `src/test` (Spring context 없는 단위 테스트, SUT 모듈에 동거) |
| `scripts/dead-letter-schema-parity-lint.sh` (3)·(4) java 검사 | **제거**. D4 에 따라 중복 FQCN 게이트가 대신한다. SQL parity 는 유지 |
| `scripts/replay-entrypoint-lint.sh` (2)·REPLAY-ENTRY-006 | **경로 변경**. 서비스 4경로 → 새 모듈 1경로 |
| `scripts/kafka-subscription-contract-lint.sh` | 유지. 서비스에 남는 `DeadLetterConsumer`/`QuarantineConsumer` 만 참조 |
| `scripts/scheduler-lock-contract-lint.sh` | 유지. `*/src/main` glob 이라 새 모듈도 자동 포함 |
| `build.gradle` `assertNoServiceProjectDeps` allowlist | **추가** |
| `build.gradle` `assertNoDuplicateGlobalFqcn` `commonDeps` | **추가**. 빠뜨리면 재복제 방지(D4)가 무력하다 |
| `Dockerfile` COPY (build.gradle 단계 + 소스 단계) | **추가** ([[project_multimodule_dockerfile_context]]) |
| `docs/02-architecture.md:513-515, 545` | **정정** |
| `.github/workflows/ci.yml` test 매트릭스 (구현 중 발견) | **추가** → platform shard. 빠지면 새 모듈 테스트가 CI 에서 조용히 사라진다 (`ci-test-matrix-lint` 가 검출) |
| `scripts/integration-test-container-lint.sh` `MODULES` (구현 중 발견) | **추가**. settings.gradle 과 대조해 누락을 위반으로 센다 |
| `LedgerOwnerWiringTest` 4벌 · `common` `ReplayHeaders` javadoc (구현 중 발견) | **정정**. 제거된 lint ID(`DLQ-PARITY-014`)와 "global/deadletter 는 4서비스 복제" 를 사실로 진술한다 |

**B1b 문자열 결합.** 테이블명·ShedLock 락 이름·토픽 리터럴은 byte 동일 사본을 옮기므로 값이 바뀌지 않는다. 해당 없음.

**B3 테스트 인프라.** 새 모듈 단위 테스트는 `com.peekcart.support.ServiceTest` 가 필요하다 → `testFixtures(project(':common'))`.

**B5 리소스 위치.** 공유 후보 중 `src/main/resources` 에 딸린 파일 없음. 마이그레이션은 서비스에 남는다.

**B6 스캔으로 떠안는 빈.** 새 모듈의 빈을 떠안는 것은 이미 같은 빈을 갖고 있던 4서비스뿐이다. 빈 집합은 바뀌지 않는다.
user-service 는 의존하지 않으므로 영향이 없다 — P9 검증으로 확인한다.

**B8.** 이번 작업은 복제의 역방향이라 해당 없음.
