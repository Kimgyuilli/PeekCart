# D-078: 캐시 이름별 수집 공백의 로컬 보완 (부분 작업)

## 1. 명제와 코드 검증

이번 무료 부분 범위는 단수 product 캐시의 수집 공백과 이름별 집계다. 누락·잘못된 counter를 0으로 표시하거나 서로 다른 cache를 합쳐 해석하면 미완이다. 전체 D-078의 운영 측정 8개가 끝났다고 표시해도 미완이다.

기준 코드 `af60cd6d9dceac541b6f457062093df70753f3ce`.

| 전제 | 코드 대조 |
|---|---|
| run-cell capture | 두 before/after loop는 products/productStock만 포함하고 product는 없다. |
| 현재 warmup | run-cell은 detail ID 순회와 list page 요청을 모두 보낸다. 과거 블록 워밍업 누락과 현재 cell warmup을 같은 것으로 쓰지 않는다. |
| metric 이름 | CacheConfig와 ProductCacheService는 product/products/productStock을 사용하고 ProductObservabilityMetricsIntegrationTest는 name/result 라벨을 검사한다. |
| collector | aggregate hit/miss만 집계하며 기존 이름별 metadata도 출력하지 않는다. |
| 운영 부작용 | run-cell은 kubectl set env 및 gcloud ssh, run-block은 apply와 DB 명령을 실행한다. 원본 runner는 이번 검증에서 실행하지 않는다. |

등급 M: runner의 metadata 표면과 collector 출력 소비 계약을 함께 보완한다. 앱 모듈·서비스 경계·CPU 정책 결정은 바꾸지 않아 새 ADR은 불필요하다. ADR-0027의 측정 불확실성도 그대로 남는다.

## 2. 작업 항목

- [x] P1. before/after 수집 이름에 product를 포함한다. 이름별 scrape 누락·실패·오염은 unavailable sentinel로 기록하고 collector에 세 이름의 counter 차분을 분리해 표시한다.
- [x] P2. 역사적 전체 누락과 새 invalid scrape의 표본 수를 분리한다. capture는 Python 3 Decimal로 원래 값을 검사해 float 반올림 전의 소수·범위 초과를 거부한다. 이름별 전체 누락·부분 누락·비숫자·비유한·음수·reset을 유효한 0으로 집계하지 않는다. 계수 유효 표본 수와 hitrate 분모가 있는 표본 수를 구분한다.
- [x] P3. fixture로 정상/이름 혼동/역사적 누락/부분 누락/invalid/reset/0분모를 검증하고 기존 aggregate 및 gate 출력의 보존을 대조한다. runner는 bash -n 및 읽기 검사만 한다.

## 3. 검증 방법

실제 collector를 임시 fixture 디렉터리에서 실행한다. 세 이름에 서로 다른 hit/miss를 주어 분리 결과를 독립 기대값과 대조한다. 누락 키나 오염값을 하나씩 주입하면 그 이름의 유효 표본에서 제외되고 0으로 대체되지 않아야 한다. aggregate가 양수인 채 이름별 counter만 역전되는 반례도 검사한다. 0/0은 유효한 계수이되 hitrate는 분모 없음으로 표시한다. 기존 코드의 동일 fixture aggregate/gate 결과와 비교해 역사적 gate 판정이 바뀌지 않았음을 확인한다. 전체 CI와 writing/consistency/diff-check도 추적한다.

TASKS/PHASE/ADR index는 root가 통합 관리하며 D-078 전체 완료로 옮기지 않는다. CI 배선 변경 없이 로컬 fixture 검증과 기존 전체 CI를 각각 보고한다.

## 검증 결과 (2026-10-21)

- Python fixture 9개 통과. 실제 collector subprocess와 runner에서 추출한 cachegets/meta 두 함수만 mock prom으로 실행했다. 운영 runner 전체나 kubectl/gcloud/DB 명령은 실행하지 않았다.
- 이름별 before/after, 여러 series 합산·이름/결과 라벨 분리, scrape 실패·빈 응답·NaN/음수/소수, metadata sentinel 직렬화, partial/reset, 0분모와 유효 표본/미수집/invalid 수를 확인했다.
- 원래 collector와 동일한 18개 fixture의 기존 합산·gate 출력이 byte 단위로 일치했다. 새 이름별 경고와 마지막 표만 제외했다. 원래 합산 capture의 누락을 0으로 보는 의미는 고치지 않았으며 그 통계의 신뢰성을 새로 보증하지 않는다.
- 잘못된 구현 5개를 임시 파일 복사본에 주입했을 때 fixture가 모두 실패했다. 원본은 변형하지 않았다.
- bash -n, Python AST 구문 검사, git diff-check와 consistency precheck를 확인한다. [재현 명령과 결과](../evidence/D-078/README.md)를 보존한다. 전체 로컬 Gradle suite는 이 collector 범위에서 실행하지 않았으며 전체 CI는 PR에서 확인한다. 별도 Codex 리뷰 미호출.

### 검증 정정

초기 named capture는 awk 숫자 변환 후 정수 여부를 검사했다. 독립 검토가 1e-999와 긴 소수의 0/1 반올림을 반증했다. Python 3 Decimal을 사용해 원래 값을 정확히 검사하고, 유한 double 범위를 넘는 입력·합계를 거부하도록 고쳤다. 추가 4개 입력을 실제 capture→TSV→collector로 검증해 모두 invalid로 제외했다. 기존 합산 경로는 이 정정에서도 변경하지 않았다.
