# D-089: 부분 publish 관측과 복구 계약

## 1. 명제와 코드 전제

일부 publish가 실패했는데6개 서비스의 해당 expected SHA 대비 latest 상태를 확인할 수 없거나 missing/read error를 성공으로 세면 미완이다. 서로 다른6개 이미지의 digest 자체가 같아야 한다고 비교하거나, 현재 관측으로 역사 unknown blob 원인을 해결했다고 기록해도 미완이다. 이 작업은 감지/추적/복구 절차의 부분 해결이며 원장애 근본 원인은 미확정으로 남긴다.

## 2. 작업 항목

- [ ] P1. 기존 publish의 push log/promotion.json/image-id와 expected SHA/service/run/attempt/push outcome을 always artifact로 남긴다. 태그/승격 command와 실패 전파는 바꾸지 않는다.
- [ ] P2. publish 부분실패 뒤에도 실행되는 단일 postpublish read-only job을 추가한다. contents/packages는read만 부여한다. six tiny evidence만 내려받고 각 서비스 expectedSHA manifest/config와그서비스 latest를 비교한다. existing verify-remote를 재사용한다.
- [ ] P3. expected SHA/current main/관측 시작끝/서비스별 원response와identity검증을 보존한다. missing·오류·형식불일치는unavailable이며 matched로 세지 않는다. currentmain 변경/다른release 가능성과 부분관측을 구분하고 집계 실패를 whole workflow에 전파한다. 관측은 원자적 snapshot이 아니다.
- [ ] P4. 기존 ci-release-gate-lint와 selftest에서 원 gate/publish 보호 및 새 read-only job 조건/권한/실패 전파 회귀를 확인한다. helper actual CLI의 정상6개(서로다른digest),부분/누락/읽기오류/config불일치/stale/concurrent/잘못된marker/전체오류, always artifact와 failure propagation을 Actions에서 대조한다. 로컬은 필요한 최소 개발 반례만 실행한다.
- [ ] P5. 같은 SHA/currentmain·새release 없음 확인 후 승인된 실패 job만 재실행하는 runbook을 작성한다. validated artifact 재사용/재빌드금지/6개 재확인/관측오류시중단을 명시한다. 자동retry/수동tag/운영deploy는 추가하지 않는다. 역사 원자료·부족한증거와 재개조건을 own evidence/audit에 보존한다.

## 3. 검증과 부분 해결 경계

정식 fixture/잘못된구현 대조/기존 release-gate 검사는 Actions에서 실행한다. 실제 원run metadata와 payment/user publish 원log는 API로 읽기 전용 확보했다. root가 승인한 무료 read-only registry/Actions 범위만 사용한다. local Gradle/Docker/GKE/실제PG/유료/수동tag/deploy 명령은 실행하지 않는다.

새 job은 main의기존 publish 뒤 첫실행으로 실제 원격증거를 남긴다. PR에서는 조건·권한·부분실패실행/전체실패전파와 actualCLI fixture를 검증하고 실제main 관측결과와 구분한다. currentmain을시작/끝에조회해expected와다르거나조회오류면완료된6개승격으로표시하지않는다. 서비스별읽기는비원자적이므로 같은순간6latest상태를증명했다고쓰지않는다.

원 unknown blob 원인은 미확정이다. 추가무료확보가능원log에 layer/digest/request/servertrace가 없으면 복구관측구현과구분해 미해결로남긴다. 재개하려면 재발run의원pushstdout/stderr/정확시각·서비스·artifact/imageID·SHA/manifest·레지스트리 응답/요청식별자 및가능한서버진단이필요하다. 새관측의성공으로그증거를대체하지않는다.

별도 Codex 리뷰 미호출. D087/PR209 및 D088/PR213 신규실패가 우선이다.

## 구현 전 추가로 확인한 수명/attempt 계약

기존 image-${service} artifact의 retention-days는1이고 새 tiny evidence는14일이다. failed publisher 재실행 전 원 image tar/checksum/ID의 현재 가용성을 확인한다. tiny receipt만으로 만료된 payload를 복구했다고 쓰지 않는다. 원 image가 없으면 publish에서 대체/재빌드하지 않고 이미 세션에서 승인된 새 정상 검증/기존 main GHCR 발행 경로를 사용한다. 추가 사용자 승인을 새로 요구하는 조항이 아니며 운영 배포와도 구분한다.

새 evidence 이름은 service+run_attempt로 고유하며 overwrite하지 않는다. 현재run의 artifact만 내려받고 모든 후보의SHA/run/service/attempt를 확인한 뒤 서비스별최신후보를선택한다. 성공5개attempt1+실패1개재시도attempt2는정상이다. 최신후보가malformed/누락/다른SHA·run이면과거valid후보로fallback하지않는다. 이전실패원본도그대로남긴다. observer가재실행됐다고가정하지않고새관측을확인하며필요시읽기전용observer job만재실행한다.

공식 Actions rerun 문서는원SHA/ref유지를명시하지만여기서artifact교체/종속job재실행을추정하지않는다. [GitHub rerun docs](https://docs.github.com/en/actions/how-tos/manage-workflow-runs/re-run-workflows-and-jobs). 기존 hosted Ubuntu에는 Buildx가있으며새 builder/setup을추가하지않고실제version probe로확인한다([runner image software](https://raw.githubusercontent.com/actions/runner-images/main/images/ubuntu/Ubuntu2404-Readme.md)).
