# D-115 — 측정 하네스의 멈춤과 오판

기준: 2026-11-13, main `937122b4`. 근거는 `loadtest/reports/2026-10-26/session-issues.md` 2·3·4·12 와
`loadtest/reports/2026-10-25/session-issues.md` 7(D-108 ⑤ 흡수)이다.

## 명제

다음 중 하나라도 성립하면 미완이다.

- `d078-s3-run.sh` 의 MySQL·Kafka 호출(초기화 포함) 가운데 시간 제한 없이 무한정 기다리는 것이 있다. 또는 초기화가 실패하거나
  시간을 넘겨도 run 이 exit 0 으로 끝난다.
- `lag_total` 이 describe 출력에서 파티션 줄을 하나도 못 읽거나 명령이 실패했는데 `0` 을 돌려준다.
- outbox 가 0 에 닿지 않은 run 의 콘솔이 "outbox 0 까지 0초" 처럼 숫자를 찍는다.
- headless Chrome 캡처 실행기가 저장소 하네스에 없거나, 장마다 시간 제한이 없다.
- `d026-run-block.sh` 워밍업 SQL 이 없는 컬럼(`quantity`)을 읽거나, 실패해도 블록이 계속된다.
- S2 의 run 단위 기록(k6 구간 `runs.tsv`·annotate·Hikari 원값·블록 전후 Pod 배치)을 하는 스크립트가 저장소 하네스에 없다.

## 작업 항목

- [x] P1. `d078-s3-run.sh` 의 `q`·`sql_file`·`lag_total` 에 시간 제한을 둔다(macOS 에 `timeout` 이 없어 세션 스크립트와 같은
  `perl alarm`). 초기화가 실패하거나 시간을 넘기면 `!!` 줄을 찍고 run 끝에서 0 이 아닌 값으로 끝낸다. 행이 말한 범위(초기화)보다
  넓다. 디스크가 가득 차면 배수 루프의 조회도 같은 이유로 멈춰 `DRAIN_LIMIT` 검사에 닿지 못하기 때문이다.
  제한은 `CALL_TIMEOUT`(기본 300초)이고, 검증에서 짧게 주려고 `DRAIN_LIMIT` 도 환경 변수로 받는다(기본 900 유지).
- [x] P2. `lag_total` 은 명령이 실패하거나 파티션 줄이 0개이면 `?` 를 돌려준다(`session-scripts/wait-payment-lag.sh` 와 같은 규칙).
  배수 루프는 `0` 일 때만 끝나므로 `?` 이면 계속 기다린다.
- [x] P3. `t_outbox0` 이 없으면 콘솔에 "outbox 0 미도달" 을 찍는다. `times.tsv` 형식은 바꾸지 않는다(이미 `-`).
- [x] P4. `session-scripts/capture.sh` 를 `loadtest/scripts/d078-capture-shots.sh` 로 옮긴다. 저장소 경로·scratch 하드코딩을
  없애고 Chrome 경로·장당 제한(기본 120초)을 환경 변수로 받는다. 1회 재시도와 실패 시 exit 1 은 유지한다.
  Chrome 의 stdin 을 `/dev/null` 로 막아 PLAN 을 읽는 루프 입력을 먹지 못하게 한다.
- [x] P5. `d026-run-block.sh` 워밍업 SQL 을 `SUM(stock)` 으로 고치고, 실패하면 `!!` 줄과 함께 exit 1 로 멈춘다(CPU 조건
  불일치와 같은 처리. 워밍업이 안 된 블록은 측정값이 콜드 버퍼풀을 담는다).
- [x] P6. `session-scripts/s2-block.sh` 를 `loadtest/scripts/d078-s2-block.sh` 로 옮긴다. 저장소 경로 하드코딩을 없애고
  `stat -f %m`(macOS 전용)은 그대로 둔다(하네스 운영 환경이 macOS).
- [x] P7. `loadtest/README.md` 스크립트 목록과 S2·캡처 절차에 P4·P6 를 적는다.

## 검증

각 항목은 가짜 `kubectl`·Chrome 을 PATH 앞에 두고 실패를 주입해 확인한다. 먼저 고치기 전 스크립트로 같은 주입을 돌려 그 실패가
재현되는지 본다.

- P1: 가짜 `kubectl` 이 초기화 SQL 에서 잠들게 하고 제한을 짧게 줘서, 제한 시간 안에 `!!` 와 0 이 아닌 exit 가 나오는지 본다.
- P2: 가짜 `kafka-consumer-groups.sh` 출력이 빈 경우, 머리줄만 있는 경우, 명령이 실패한 경우에 `?` 를 받고, 정상 출력은 합계를 받는다.
- P3: outbox 가 계속 PENDING 인 가짜로 `DRAIN_LIMIT` 를 짧게 넘겨 콘솔 문구를 본다.
- P4: 잠드는 가짜 Chrome 으로 장당 제한과 재시도 뒤 `FAIL` 및 exit 1 을 보고, 정상 가짜로 `ok` 를 본다.
- P5: 가짜 `mysql` 이 `quantity` 를 거부하게 해서 옛 SQL 은 멈추고 새 SQL 은 지나가는지 본다.
- P6: 가짜 `kubectl`·`d026-run-cell.sh` 대신 쓸 k6 로그로 한 셀을 돌려 `runs.tsv` 한 줄과 Hikari JSON 두 개가 생기는지 보고,
  k6 로그에 `running (...)` 줄이 없으면 `!!` 를 찍고 건너뛰는지 본다. `git grep /Users/ -- loadtest/scripts` 0건. 실제 S2 블록은
  GKE 세션이 필요해 범위 밖이다.
