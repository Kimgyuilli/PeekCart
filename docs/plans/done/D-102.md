# D-102: 테스트 주석의 의미와 출처 정리

## 1. 명제와 코드 검증

Java `src/test` 주석에 문맥 없이 복원할 수 없는 계획 내부 식별자가 남거나, 유용한 ADR·전역 부채·코드 내 시나리오 근거까지 지우거나, 재발 감시 조건을 찾을 수 없으면 미완이다.

기준 코드 `be535c57`. 문자열·문자·text block을 제외한 초기 Java comment scan의 후보는 219줄/113파일이다. 보충 패턴까지 합친 최종 inventory는 247줄/117파일이며 현재 Java src/test 전체 모집단은 204파일이다. 이는 실제 부채 수가 아니다. `실행계획` 같은 일반 용어, ADR이 정의한 `P1-D`, 파일 안에 의미가 정의된 시나리오 라벨도 포함한다. 공유 messaging 모듈의 후보는 3줄/2파일이며 전체 테스트 범위를 대상으로 처분한다.

| 전제 | 코드 대조 |
|---|---|
| replay·publication-unknown 권한 | DeadLetterEndpoint가 ADMIN 및 인증 주체 기반 actor를 검사한다. 기존 ADR-0022 §D4 링크는 유효하다. |
| outbox polling 범위 | findPendingEvents(batchSize)로 자기 스키마의 후보를 읽고 publish/cycle timeout으로 실행을 제한한다. 기존 'PENDING 전체' 주석을 좁힌다. |
| 주석과 실행 코드 | DisplayName·assertion 문자열·method 이름은 실행 토큰으로 보존한다. 주석 안 계획 식별자는 동작의 이름이나 ADR 근거로 풀어 쓴다. |
| 동시 작업 | payment ApprovalLedgerIntegrationTest는 worker C의 frozen head `651044a`와 대조했다. C 변경은 beginApproval 인자이며 이 작업의 header 주석과 겹치지 않는다. 다른 작업의 구현을 부분 cherry-pick하지 않는다. |

등급 M: 여러 모듈의 테스트 주석만 변경한다. API·이벤트·DB·설정 계약 및 아키텍처 결정을 바꾸지 않으므로 새 ADR은 불필요하다. 최초 공유 모듈 3줄 범위에서 repository-wide comment 정리로 확대했다.

## 2. 작업 항목

- [x] P1. 모든 후보 주석을 의미·근거 기준으로 분류하고 opaque 출처를 제거하거나 현재 행동 설명으로 바꾼다. ADR·전역 부채·로컬 정의 시나리오는 보존한다.
- [x] P2. 후보 inventory와 재발 감시 규칙을 저장한다. 기존 metadata 문자열 잔존은 comment 범위와 구분한다.
- [x] P3. 실행 토큰·기존 ADR/debt 참조의 부분집합 보존 및 식별자 검사 음성/양성 대조군을 검증하고 전체 CI를 추적한다.

## 3. 검증 방법

| 대상 | 잘못된 변경을 드러내는 검사 |
|---|---|
| 주석 의미 | 초기 219 후보 각 행에 변경/보존 사유를 남기고 최종 후보를 다시 읽는다. '실행계획', ADR 정의 표면, 파일 내부 시나리오는 무조건 지우는 검사를 쓰지 않는다. |
| 코드 무변경 | JDK 17 compiler scanner의 token kind + 원문 spelling 열을 기준 SHA와 비교한다. assertion 값 변이를 주입하면 실패해야 하며 DisplayName·text block도 토큰에 포함한다. |
| 검색 경계 | comment에 `계획 P24`를 주입하면 찾고 `ADR-0022 §D4 · D-050` 및 문자열 내부 같은 텍스트는 debt로 세지 않는지 확인한다. |
| 출처 | 기존 ADR·D-/L- 전역 식별자의 주석 내 집합이 사라지지 않는지 비교한다. |
| 출하 | diff-check, plan grade/preflight/consistency, 관련 lightweight lint, commit/PR writing lint. 전체 test는 PR 전체 CI로 확인한다. |

## 미해결

DisplayName/assertion 등 문자열의 역사 라벨은 주석 밖 실행 토큰이므로 변경하지 않는다. SQL/YAML/스크립트와 main 코드는 이번 범위 밖이다. CI 전수 lint는 새로운 opaque comment 재발이 확인되면 별도 후속으로 도입한다. D-088 일반 lint 생존/배선 문제에 합치지 않는다. TASKS/PHASE/ADR index 완료 처리는 root가 관리한다.
