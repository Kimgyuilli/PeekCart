# D-108 마지막 재측정: 수신 상한 대조와 D-078 ⑤⑥ 측정

> 과금 세션 1회로 측정을 끝낸다(2026-10-25 사용자 결정: 측정을 막는 부채만 해결하고 재측정한다). **세션을 실행하기 전까지 이
> 계획서는 아카이브하지 않는다.** 세션 실행 기록도 이 파일 §5 아래에 남긴다.

기준: 2026-10-25, main `4293cba`. 지난 계획 [D-078-remeasure-plan](D-078-remeasure-plan.md), 증적

## 1. 명제

다음 중 하나라도 성립하면 미완이다.

- 세션에서 무엇을 어떤 순서로 재고 언제 멈출지가 결과를 보기 전에 정해져 있지 않다. 워밍업 종료 기준(D-108 ④), 수신 상한
  대조의 순서와 판정(D-108 ①), 어느 설정도 초당 170건에 닿지 못할 때의 종료 규칙 중 하나라도 이 계획서에 없다.
- 대조 설정(product outbox 5s·4s·100)을 렌더할 수 없거나, 렌더 차이가 product-service env 세 줄을 넘거나, env 이름이 설정 키의
  환경변수 규칙(하이픈 제거, 대문자)과 다르다.
- S3 run 스크립트가 산출 경로·USERS·RPS·DUR 을 인자로 받지 않아 세션 안에서 손으로 고쳐야 한다.
- 워밍업 수렴 판정에 2026-10-25 원 요약(w3~w6)을 넣었을 때 w6 만 수렴으로 나오지 않는다.

배경: 2026-10-25 세션은 S3 에서 수락이 초당 약 122건에서 멈춰 모든 run 이 무효였다(D-108 ①). 남은 지표인 D-078 ⑤(낙관락
충돌률·DLQ 유입, ADR-0025 C 승격 게이트), ⑥(스케줄러 풀 4, D-024), ADR-0045 검증(만료 취소·사가 왕복 p99)은 모두 S3 에서
나오므로 이 상한만 측정을 막는다. D-108 ②③⑤⑥ 과 D-109 는 측정을 막지 않아 이번 범위가 아니다(§9).

## 3. 사전 규칙

### 3.1 워밍업 종료 (D-108 ④)

- 워밍업 run 은 측정과 같은 조건(같은 RPS·USERS·DUR, contend)으로 돌고, 원자료는 `warmup/` 에 두며 분석에 쓰지 않는다.
- 콜드 JVM(첫 배포, overlay 재적용 뒤)은 워밍업을 2회 이상 돈다. 직전 워밍업 run 대비 수락 건수 변화가 5% 이내이고 그 사이
  order·product 재시작이 없으면 워밍업을 끝낸다. 최대 4회이고, 4회 안에 수렴하지 않으면 그 설정은 미달이다.
- 같은 Pod 에서 설정만 바꾸면(C1) 워밍업 1회를 버리고 판정 run 으로 간다. 수렴 판정은 하지 않는다.
- 근거: 10-25 의 새 JVM 은 +82%, +25%, +4.1% 로 네 번째 run(w6)에서 수렴했다. 170건에 닿는 설정은 수락이 목표(10,200)에 붙어
  바로 수렴한다.
- 판정은 `d078-warmup-check.py` 가 두 요약 JSON 으로 계산해 찍는다(P2). 세션 중에 임계나 횟수를 바꾸지 않는다.

### 3.2 수신 상한 대조 (D-108 ①)

설정은 이 순서로만 돈다. 앞 설정이 통과하면 뒤 설정은 돌지 않는다.

| 설정 | 바꾸는 것 | 맞춰 보는 원인 후보 |
|---|---|---|
| C0 | 없음. `gke-d078-contention`, USERS 450 | 세션마다 다른 디스크·Pod 배치. 통과하면 base 그대로 잰다 |
| C1 | k6 USERS 200 (같은 Pod) | USERS 450 의 동시성 |
| C2 | product outbox 5s·4s·100 (`gke-d078-contention-product-outbox-5s`), USERS 450 | ADR-0045 로 늘어난 product 커밋 |

- 판정 run: 워밍업이 끝난 뒤 첫 contend run 이다. 유효(dropped 가 한도 이하)면 그 설정은 통과이고 그 run 이 측정 `c1` 이 된다.
  무효면 한 번 더 돌리고, 두 번 모두 무효면 그 설정은 미달이다.
- 판정 run 마다 `d078-mysql-sampler.sh` 로 MySQL 표본을 남긴다(커밋 대기·fsync 의 비교 근거). 표본은 k6 setup 이 끝난 뒤
  부하 구간에 떠야 하므로 `DELAY` 를 setup 시간에 맞춘다(로그인 1명 약 0.25초라 USERS 450 은 기본값 125초, USERS 200 은 55초).
- C2 는 첫 run 의 배수 구간에서 product PENDING 감소가 초당 20건 이하(5초에 100건)여야 덮어쓰기가 먹은 것이다. 넘으면 C2 를
  결함으로 접고 §3.4 로 간다.
- 기록: 통과한 설정이 원인 후보를 가리킨다. C1 은 C0 뒤라 JVM 이 더 데워진 순서 효과가 있으므로 단정하지 않고 "후보와 맞는다"로
  적는다.

### 3.3 측정 블록 (D-078 ⑤⑥, ADR-0045)

통과한 설정에서 지난 계획 S3-4~8 을 따른다. `c1`(판정 run), `c2`, `c3` 는 contend, `s1` 은 spread 다. 무효인 측정 run 은 모드마다
2회까지 다시 돈다. 읽는 법도 같다. ⑤ 는 DLQ/주문 비율의 중앙값과 범위를 Phase 4(0.072%)·2026-10-24 와 나란히 적고, ⑥ 은 배수
구간의 executor 지표를 보며, 만료 취소·사가 왕복 p99·product backlog 는 ADR-0045 재검토 조건 1 의 입력이다.

C2 에서 잰 값은 base(ADR-0045)가 아니라 2026-10-24 와 같은 product outbox 조건의 값이라고 함께 적는다. ADR-0045 검증은 C0·C1
에서 잰 경우에만 성립한다.

### 3.4 종료 규칙

- C0·C1·C2 가 모두 미달이면 C0 overlay 를 다시 적용하고 RPS_F 로 측정 블록을 돈다. RPS_F 는 C0 판정 run 의 초당 수락에 0.9 를
  곱해 10 단위로 내린 값이다. 10-25 값(초당 약 122건)이면 100 이다. 부하 한도는 k6 가 RPS_F 로 다시 계산한다.
- RPS_F 에서도 무효면 측정을 접는다.
- 어느 경우든 이 세션으로 D-078 ⑤⑥ 과 D-108 ① 을 닫고 추가 과금 세션은 없다. 170건 미달로 닫으면 ⑤ 는 같은 부하 비교가 안 되어
  ADR-0025 C 승격 판단을 보류하고 현행(낙관락과 jitter)을 유지한다고 적는다.
