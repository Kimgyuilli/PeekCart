# D-052 — TASKS.md 완료 항목 아카이브 + 완료 시 이동 규칙

## 1. 명제

아래 중 하나라도 성립하면 미완이다.

- `docs/TASKS.md` 에 `✅` 상태 행이나 종결된 섹션(Phase 4 · 보류 · 버킷 1)이 남아 있다
- 완료 처리 절차(`/ship` Step 8 · `/done`)가 완료 행을 `TASKS.md` 안에서 `✅` 로 바꾸는 데서 끝난다. 그러면 파일이 다시 커진다
- 행을 옮긴 뒤 `harness-context.sh` 나 `hpx_ship_resume_point` 가 틀린 값을 낸다. 완료 카운트가 줄거나, 링크가 아카이브에 있는 PR 을 `/done` 미적용으로 판정하는 경우다
- 옮기는 과정에서 행이나 문단이 하나라도 사라지거나 바뀐다

### 2-3. PLAN-BLINDSPOTS

- **B1 역의존 스윕**: `git grep 'TASKS\.md'` 결과 중 `docs/plans/done/`(이력) 을 제외한 인바운드 간선.
  - `.claude/commands/*` · `.claude/scripts/lib/ship.sh` · `scripts/harness-context.sh` 는 §2-2 표에서 처분했다
  - `docs/adr/0007:107`(D-006), `0008:71`(D-007), `0009:139`(D-005), `0023:179`(D-020), `0025:149`(D-025), `0026:169`(D-026·D-002), `0027:168`(D-023) 은 **유지**한다. ADR 은 immutable 이다. 이동 후 `TASKS.md` 부채 섹션 머리에 "완료 행은 `TASKS-done.md`" 포인터를 둬서 한 번 더 따라가면 도달한다. D-005~D-007 은 이미 phase1-3 아카이브에 있어 현재도 같은 한 단계 간접이다
  - `docs/07-roadmap-portfolio.md:123` · `docs/progress/PHASE5.md:4,19` 는 `§개발 부채 / 작업` 섹션을 가리킨다. 섹션은 남으므로 **유지**한다
  - `docs/progress/PHASE3.md` · `PHASE4.md` · `phase4-prep-debt-roadmap.md` · `docs/review/final-report.md` 는 당시 시점의 이력 서술이다(Layer 3). **유지**한다
- **B1b 문자열 결합**: 파일 경로 리터럴 `docs/TASKS.md` 를 쓰는 스크립트는 `harness-context.sh` · `ship.sh` · `consistency-hints.sh` 셋이다. §2-2 에서 처분했다. 행 **내부**의 상대 링크는 `TASKS.md:73`(D-029 행) `](./adr/0027-...)` 하나다. `docs/progress/` 로 옮기면 `../adr/` 로 바꿔야 한다 (P2)

- B2 · B3 · B5~B12 는 코드 · 모듈 · 이벤트 대상이다. 해당 없다

### 2-4. 설계 선택

- **아카이브를 둘로 나눈다.** Phase 4 · 보류 섹션은 닫힌 스냅샷이라 `TASKS-archive-phase4.md` 에 한 번 옮기고 다시 손대지 않는다. 선례는 `TASKS-archive-phase1-3.md` 다. 완료 D- 행은 앞으로도 계속 붙는 목록이라 `TASKS-done.md` 로 분리한다. 한 파일에 섞으면 "phase4" 이름의 파일이 Phase 5 이후 행으로 자란다
- **완료 행은 원문 그대로 옮긴다.** 요약하지 않는다. ADR 이 행 번호로 가리키는 근거가 행 본문에 있다
- **"다음 번호 = D-058" 을 없앤다.** 이 값은 매 등록마다 사람이 고쳐야 하는 카운터인데 이미 틀려 있다(실제는 D-059). "`TASKS.md` · `TASKS-done.md` 의 최대 번호 + 1" 이라는 규칙으로 바꾼다
- ADR 선행 판단(§3): 외부 의존 · 아키텍처 경계 · 인프라 변경이 없다. 되돌림은 하네스 파일 안에서 끝난다. ADR 은 필요 없다
