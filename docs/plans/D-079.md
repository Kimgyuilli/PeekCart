# D-079 — 측정 overlay 기본 렌더 복구

## 1. 명제
4개 측정 overlay 중 하나라도 기본 `kubectl kustomize`에 실패하거나 수정 전 제한 해제 렌더와 리소스 의미가 달라지면 미완이다.

## 2. 배경과 코드 검증
| 전제 | 확인 및 처분 |
|---|---|
| gke-d002a, gke-d002bc, CPU 500m/2000m 기본 렌더 실패 | kubectl v1.35.3 / Kustomize v5.7.1에서 네 overlay 모두 exit 1, base/namespace.yml root 이탈 오류 재현. 제한 해제 시 모두 성공 |
| 측정 스택은 base 일부만 필요 | a는 product/infra/내부 공개키, bc는 gateway/user/product/order/payment/infra/두 공개키. 전체 base+삭제 패치는 새 base 리소스 유입 위험이 있어 채택하지 않음 |
| 기존 YAML을 복사할 필요 없음 | 각 infra/service 디렉터리에 측정용 Kustomization 진입점을 두고 기존 리소스 파일을 참조. namespace와 공개키 2개만 전용 디렉터리로 이동 |
| 경로 역참조 | base kustomization, a/bc, minikube-rotation-drill 참조를 갱신. scripts/CI에 해당 파일 직접 참조 없음. ADR-0006·완료 계획·progress의 과거 경로는 역사 기록으로 유지 |
| 기존 운영 base | base 리소스 목록/monitoring/정책 유지. base·gke·minikube 및 회전 드릴 제한 해제 렌더와 변경 전후 동일성 확인 |

인프라 리소스 집계 구조 변경이므로 보수적으로 L. 외부 의존성·환경·네임스페이스·서비스 경계 및 배포 리소스 계약은 바뀌지 않아 새 ADR 불필요(ADR-0005/0006 유지).

PLAN-BLINDSPOTS: B1/B1b 위 역참조 표에 반영, B2 기존 파일 확인, B4/B5 하위 Kustomization으로 동일 원본 재사용. B3/B6~B12는 Java 모듈·빈·DB·이벤트 변경이 없어 비해당. 공개키 원본은 단일 위치로 유지한다.

## 3. 작업 항목
- [x] P1. 하위 Kustomization과 세 리소스 디렉터리 이동, 모든 실행 경로 참조 갱신.
- [x] P2. 기본 렌더를 기존 CI namespace lint 범위에 포함하고 CPU overlay 렌더 안내 정정.
- [x] P3. 네 측정 및 base/운영/드릴 렌더 동일성, 기본 렌더 회귀 주입, 관련 lint 검증.

## 4. 검증 방법
- 변경 전 4개 기본 렌더 실패 및 제한 해제 성공 산출물을 저장한다. 변경 후 YAML 문서의 `(apiVersion, kind, namespace, name)` 기준 정규화 비교로 모든 필드의 동일성을 확인한다.
- base, gke, minikube, 회전 드릴도 같은 비교를 적용한다. 드릴은 기존 제한 해제 명령 계약만 유지한다.
- 임시 복사본에서 a의 namespace directory 참조를 디렉터리 밖 파일 직접 참조로 되돌려 namespace lint가 실제 실패하는지 확인한다.
- CI namespace lint와 인프라 관련 lint 실행. `./gradlew test`는 메인의 자원 조율 및 최종 통합 검증으로 수행하고 개별 미실행 사실을 명시한다.

## 5. 완료 조건과 미해결
P1~P3 검증 완료, 배포 리소스 동일성, 최종 통합 Gradle 및 lint 결과를 확인해야 전체 완료. 실제 배포·클러스터 측정, 회전 드릴 전체 root 이탈 개선은 범위 밖이며 기존 동작을 보존한다. 별도 Codex 리뷰 미호출.
