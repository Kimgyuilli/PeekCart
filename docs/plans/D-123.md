# D-123 — CI 이미지 캐시의 PR 쓰기 중단

## 1. 명제
아래가 성립하면 미완이다.
- PR run 의 `images` job 이 Docker 레이어 캐시를 PR merge ref 에 쓴다. 그 캐시는 다른 PR 이 읽지 못하는데 저장소 GHA 캐시 한도(10GB)를
  채워, Gradle 의존성 캐시와 main 레이어 캐시를 밀어낸다. 캐시를 잃은 job 은 Maven Central 에서 의존성을 다시 받고 요청 제한(429·404)과
  빌드 중 blob 누락으로 떨어진다.

### 코드·실측 검증 (2026-11-20, main `3800d1cf`)
| 전제 | 확인 결과 |
|---|---|
| 캐시 구성 | 2026-11-20 저장소 GHA 캐시 16.46GB. Docker 레이어 캐시 PR ref 15.92GB(844개), main 0.28GB(26개), Gradle 의존성 캐시(`setup-java` `cache: gradle`) 0.26GB(1개). PR ref 분은 지울 때 보니 전부 이 PR(#274)의 run 3번이 쓴 것이었다(run 당 약 5GB, 사전 다운로드 레이어 포함). 2026-11-19 실패 당시 사용량은 남아 있지 않다. PR 4개와 재실행이 run 마다 같은 방식으로 캐시를 쓴 것이 한도를 넘긴 원인이라는 것은 추정이다 |
| 쓰는 곳 | `ci.yml` `images` job `Build image` 의 `cache-to: type=gha,mode=max,scope=image-<svc>` 가 이벤트와 무관하게 쓴다. CI 는 main push 와 main 대상 PR 에서만 돈다 |
| 증상과의 연결 | run 44583989636 에서 images job 6개 모두 COPY 단계부터 캐시를 읽지 못했다. run 44550802629 의 bootJar blob 누락, run 44556096719·44559409533 의 bootJar jar 404, test job 의 Maven Central 429 가 같은 시간대에 났다 |
| 소비자 | `ci-build-profile-selftest.py` `test_workflow_and_final_runtime_contract` 가 `cache-to` 값을 고정 단언한다. profile export 단계는 `cache-from` 만 쓴다 |

사용자 결정(2026-11-20): 최소 복잡도로 근본 원인만 고친다. ADR 선행 신호 없음.

### 정정 이력
- 초안(2026-11-19)은 증상 두 갈래를 따로 처분했다. 빌드 증거 검사가 캐시 불러오기 실패 뒤 재실행을 실패로 보는 문제는 검사 로직을 고치고,
  bootJar 의 jar 404 는 Dockerfile 에서 jar 를 미리 받고 `--offline` 으로 바꿨다. PR CI 에서 사전 다운로드가 캐시 미스로 매번 다시 돌며
  같은 원격 실패를 냈고, 재시도 대기까지 늘렸다. 캐시 사용량을 나눠 보고서야 둘 다 PR ref 캐시가 한도를 채운 결과라는 것을 확인했다.
  덧붙인 변경(검사 로직, 사전 다운로드·오프라인, 재시도)은 모두 걷어냈다.

## 2. 작업 항목
- [x] P1. `ci.yml` `Build image` 의 `cache-to` 를 main push 일 때만 쓰게 한다. PR 은 `cache-from` 으로 main 캐시를 읽기만 한다.
- [x] P2. `ci-build-profile-selftest.py` 의 `cache-to` 단언을 새 값으로 바꾼다.
- [x] P3. (범위 추가) `scripts/fixtures/flyway-contract/payment-baseline-tests.json` 에서 #271(D-121)이 이름을 바꾼 `PaymentEventConsumerTest`
      테스트 1건을 새 이름으로 교체한다(334건 유지). Flyway contract 워크플로는 경로 필터라 #271 에서 돌지 않았고 이 PR 의 중간 커밋에서 드러났다.
- [x] P4. 이미 쌓인 PR ref 의 Docker 레이어 캐시를 한 번 지운다(재생성 가능한 데이터, main ref 캐시는 남긴다).

## 3. 검증 방법
- V1: selftest 통과. `cache-to` 를 원래 값으로 되돌리면 `test_workflow_and_final_runtime_contract` 가 실패한다. `--mutants` 통과.
- V2: PR CI 에서 images job 의 `Build image` 가 캐시를 내보내지 않는다(`exporting to GitHub Actions Cache` 없음). 병합 뒤 main push run 은 내보낸다.
- V3: 정리 뒤 저장소 GHA 캐시 크기가 한도 아래인지 확인한다.
- V4: payment baseline fixture 를 로컬 payment 테스트 XML 과 대조해 누락 0.

## 미해결
- 첫 main push 가 캐시를 다시 채우기 전까지 PR 은 캐시 미스로 빌드한다. 처분: 병합 직후 main run 이 채운다.
- Docker Hub base 이미지 resolve 실패(2026-10-24)는 다른 경로다. 처분: 범위 밖.
