# D-123 — CI 이미지 빌드의 간헐 실패 처분

## 1. 명제
아래가 성립하면 미완이다.
- 2026-11-19~20 CI 실패의 직접 원인이 무엇인지, 코드로 고칠 대상인지가 기록되지 않았다.

### 확인한 사실 (2026-11-20, main `3800d1cf`)
| 항목 | 확인 결과 |
|---|---|
| 직접 원인 | test job 이 `repo.maven.apache.org` 에서 `Received status code 429 from server` 를 받았다(PR #274 run 2026-11-19 17:50, 18:35). 이미지 빌드의 bootJar jar `Could not find`(404)와 플러그인 해석 실패도 같은 시간대(2026-11-19 15시 이후)에 났다 |
| 이전 이력 | 최근 150 run 중 이 갈래의 실패는 2026-11-19 이후에만 있다 |
| blob 누락 | run 44550802629 는 buildkit 이 캐시 적중을 알린 뒤 GHA blob 을 못 불러와 단계를 다시 실행했고 이미지는 정상으로 만들어졌다. 빌드 증거 검사가 중간 오류 이벤트로 실패시켰다 |
| 캐시 배경(추정) | 2026-11-20 저장소 GHA 캐시는 16.46GB(한도 10GB)였으나 PR ref 분 15.92GB 는 PR #274 자신의 run 3번이 쓴 것이었다. 2026-11-19 당시 사용량은 남아 있지 않아, 캐시 축출이 원격 다운로드를 늘렸다는 설명은 검증하지 못했다 |

사용자 결정(2026-11-20): 최소 복잡도. 외부 원인(Maven Central 요청 제한)은 코드로 고치지 않고 재실행으로 처리한다.

### 정정 이력
- 초안(2026-11-19)은 증상별로 빌드 증거 검사 로직 수정, Dockerfile jar 사전 다운로드와 `--offline`, 재시도 대기를 넣었다. 사전 다운로드가
  캐시 미스로 매번 다시 돌며 같은 원격 실패를 냈다.
- 2차(2026-11-20)는 원인을 PR ref 캐시의 한도 초과로 보고 `cache-to` 를 main push 전용으로 바꿨다. 빌드 증거 검사가 캐시 내보내기 단계를
  필수로 요구해 PR 이미지 job 이 새로 실패했고, 캐시 정리 때 인덱스 항목을 남겨 blob 누락을 다시 만들었다. 근거로 쓴 15.92GB 도 이 PR 의
  실행분이었다.
- 모두 되돌렸다. 남은 변경은 아래 P1 하나다.

## 미해결
- Maven Central 요청 제한이 계속되면 다시 본다. 그때는 캐시 사용량을 실패 시점에 측정해 축출과의 관계를 먼저 확인한다.
- blob 누락 뒤 재실행으로 끝난 빌드를 빌드 증거 검사가 실패로 보는 문제는 남는다. 같은 실패가 반복되면 다룬다.
- Docker Hub base 이미지 resolve 실패(2026-10-24)는 다른 경로다.
