# D-123 — CI 이미지 빌드의 의존성 다운로드와 캐시 복구 판정

## 1. 명제
아래 중 하나라도 성립하면 미완이다.
- `scripts/ci-build-profile.py` 가 bootJar vertex 의 캐시 불러오기 실패 뒤 재실행으로 정상 완료된 빌드를 `invalid/failed bootJar cache event` 로 실패시킨다.
- 이미지 빌드의 `bootJar` 단계가 Maven Central 에 접속한다. 그래서 build.gradle 이 바뀌지 않은 PR 도 원격 저장소의 일시 응답 실패(404)로 떨어진다.
- 의존성 레이어가 다운로드 실패를 `|| true` 로 삼켜, 불완전한 상태가 레이어 캐시에 남을 수 있다.

사용자 결정(2026-11-19): 둘 다 처분한다(검사 스크립트 수정 + jar 사전 다운로드와 오프라인 bootJar). 등급 M.

## 2. 작업 항목
- [x] P1. `scripts/ci-build-profile.py` `cache_vertex`: bootJar vertex 의 오류 이벤트는 그 digest 의 누적 상태(`cached`·`completed`)를 초기화하고 표시만 남긴다. 그 뒤 오류 없는 완료가 오면 그 상태로 판정하고, 마지막 오류 뒤 완료가 없으면 지금처럼 실패한다. 오류가 있었는지는 결과에 `cache_load_recovered: true` 로 남긴다(근거 없이 숨기지 않는다).
- [x] P2. `gradle/prefetch-dependencies.init.gradle` 추가: 모든 프로젝트에 `prefetchDependencies` 태스크를 등록해 위 네 configuration 의 외부 모듈 artifact 를 resolve 한다.
- [x] P3. `Dockerfile`: 의존성 단계를 `./gradlew --init-script gradle/prefetch-dependencies.init.gradle prefetchDependencies --no-daemon` 로 바꾸고 `|| true` 를 뺀다. 실패하면 10초 간격으로 최대 3회 시도하고, 그래도 실패하면 빌드를 실패시킨다(불완전한 레이어가 캐시에 남지 않게). bootJar 단계에 `--offline` 을 더한다. 머리 주석에 이유를 적는다.
- [x] P4. `scripts/ci-build-profile-selftest.py`: 복구 경우(cached → error → 재실행 완료 + 실행 로그)가 `fresh_execution` 이고 `cache_load_recovered` 가 참인 테스트, 오류 뒤 완료가 없는 경우의 실패 테스트, Dockerfile build 단계가 `--offline` bootJar 와 `|| true` 없는 사전 다운로드를 쓰는지의 단언. mutant 하나(오류 초기화 제거)를 더한다.

## 3. 검증 방법
- V1 단위(selftest): 복구 경우가 통과하고 `measurement_status == 'fresh_execution'`. 오류 뒤 완료가 없으면 exit 2. 기존 materialize 경우가 그대로 cache hit 로 판정된다. `--mutants` 에서 "오류 이벤트에서 초기화하지 않음" 변이가 새 테스트로 거부된다.
- V2 실 증거 재판정: run 44550802629 의 실제 artifact(`image-progress.jsonl`)를 수정 전 `cache_vertex` 에 넣으면 실패하고 수정 후 통과하는지 확인한다(digest 1개, cached False).
- V3 로컬 이미지 빌드: `docker build --build-arg SERVICE=gateway --target runtime .` 와 `order-service` 를 돌려 성공하는지 본다. 사전 다운로드 단계에서 init script 를 빼거나 bootJar 에서 `--offline` 을 유지한 채 사전 다운로드를 원래 `dependencies` 로 되돌리면 bootJar 가 offline 오류로 실패하는지 대조한다(오프라인이 실제로 강제된다는 확인). `scripts/docker-health-smoke.sh gateway:<tag>` 를 돌린다.
- V4 회귀: `python3 -B scripts/ci-build-profile-selftest.py`·`--mutants`, ci.yml `Run CI policy lints` 블록 전부, `scripts/*-lint.sh`. PR CI 의 images job 6개가 통과하는지 본다.

## 미해결
- Docker Hub base 이미지 resolve 실패(2026-10-24 run 40129543377)와 test job 의 Testcontainers 기동 실패(2026-11-19 두 건)는 다른 경로다. 처분: 이번 범위 밖. 반복되면 별도 행으로 올린다.
- 의존성 레이어가 캐시에 없을 때(build.gradle 변경 또는 GHA 캐시 축출)는 여전히 Maven Central 에 접속한다. 3회 재시도가 그 구간을 덮는다.
- bootJar 단계가 jar 다운로드를 하지 않게 되어 빌드 프로파일(D-087)의 bootJar 시간이 다운로드분만큼 줄어든다. 과거 profile 값과 비교할 때 측정 조건 차이로 적는다.
