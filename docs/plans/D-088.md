# D-088: lint CI 배선과 외부 생존 대조

## 1. 명제와 코드 전제

새 `scripts/*-lint.sh`가 CI 소비자 없이 추가되거나, 검사기 이름을 주석/echo/사용하지 않는 heredoc/비활성 step에만 적어도 배선으로 인정하면 미완이다. 지정4개 검사기의 앞부분을 `echo OK; exit 0`으로 바꿔도 외부 음성 fixture가 통과하면 미완이다. 기존19개 inline selftest의 존재만으로 그19개 모두의 early-exit 생존을 증명했다고 쓰는 것도 미완이다.

기준 actual main `3bb01bbc3190a9aa38a7b4e6faec7bb767117808`에서 실제 source를 읽었다. D087/PR209는 images와 policy의 다른 위치 두 줄을 소유하며 본 작업은 main 기반 독립 PR이다. 공유 TASKS/PHASE/master와 기존 lint 판정 규칙은 수정하지 않는다.

| 전제 | 직접 확인 |
|---|---|
| 모집단 | `scripts/*-lint.sh`는24개다.23개는 ci.yml run에 literal bash 호출이 있고 writing-lint만 ship 소비자다. 동적 파일 목록을 검사해 새 누락을 잡는다. |
| 기존 자기검증 | 위23개 중19개는 CI에서 --self-test로 호출된다. 이 호출은 정적 배선 근거이며 임의 early exit에 대한 외부 생존 증거는 아니다. |
| 외부 대조 대상4 | scheduler-lock-contract/image-contract/kustomize-namespace/observability-ssot는 자체 selftest가 없다. 각각 script 위치로 repo root를 정하므로 actual script를 임시 root/scripts에 복사하고 실제 기본 entrypoint를 실행할 수 있다. 새 root override나 inline dispatch는 필요 없다. |
| 실제 의존성 | scheduler/SSOT는 Bash mapfile을 사용한다. namespace는 실제 kubectl kustomize와 PyYAML, image는 Python과 shell을 쓴다. CI가 이미 설치한 Bash/Python/PyYAML/kubectl을 재사용한다. cluster 연결 명령은 없다. |
| 예외 | writing-lint는 commit/PR 문체 검사로 `.claude/commands/ship.md`에서 --commits/--file/--title 소비된다. 전역 CI source 문서 검사가 아닌 이유를 고정하고 소비자 소실/새 예외를 거부한다. |

등급 M은 공유 CI lint gate 변경 때문이다. 제품/배포/외부 의존성/아키텍처 경계 변경이 없어 새 ADR은 불필요하다. 외부 fixture helper1개와 작은 wiring lint1개만 추가하고 registry/config/wrapper 또는 범용 shell parser는 만들지 않는다.

## 2. 작업 항목

- [ ] P1. 현재24개와 run 소비자/19개 inline selftest/4개 외부 fixture/ship-only 예외를 검사한다. YAML job/step의 disabled/continue-on-error 소비자를 인정하지 않는다. literal direct bash command로 지원 범위를 좁히고 복합 shell/heredoc/여러 줄 quote를 억지로 해석하지 않는다.
- [ ] P2. 4개 actual 기본 shell entrypoint의 정상과 계약 위반 fixture를 외부에서 실행한다. scheduler 락/fixedRate/pool, image matrix/base/rewrite, namespace 실제 local render, SSOT YAML/Java owner를 확인한다. 각 script의 early-exit0와 always-reject poison이 paired control을 실패시키는지 검사한다.
- [ ] P3. wiring 정상/누락/새 script/가짜 주석·echo·heredoc·quoted 호출/disabled step/자기검증 누락/예외 소비자 소실을 실제 CLI 대조로 확인한다. 기존 policy step의 두 child rc23 실패 전파를 검사한다.
- [ ] P4. 기존 PyYAML 설치 뒤 policy step에 두 줄만 연결한다. 실제 Actions 결과/정확 source/검증 모집단과 한계를 own audit/evidence에 보존하고 독립 검토를 받는다. shared 완료 기록은 root에게 전달한다.

## 3. 검증과 한계

로컬은 필요한 최소 개발 반례만 실행하고 정식 전체 fixture/poison 및 기존 lint는 Actions에서 실행한다. namespace fixture는 `kubectl kustomize`만 사용하고 apply/cluster/ssh/Gradle/Docker/유료 명령은 실행하지 않는다.

CI 소비자 검사는 현재 구조의 literal direct bash 호출과 명시적으로 지원한 job/step 조건에 관한 정적 계약이다. arbitrary shell의 모든 실행 경로나 모든 기존 검사기의 정확성은 증명하지 않는다. 외부 early-exit/always-reject 생존 대조의 직접 보장 범위는 지정4개다. 나머지19개의 inline selftest 배선은 계속 강제하되 외부 poison 생존을 통과했다고 표시하지 않는다. 새로운 lint는 CI 호출과 selftest 배선 또는 별도 검토된 외부 대조가 없으면 실패한다.

사용하지 않는 heredoc/여러 줄 quote를 포함한 run block은 소비자 증거로 쓰지 않는다. 현재 유효23개는 그러한 block 밖에 지원된 소비자가 있다. 복합 shell로 소비자를 옮기면 단순한 별도 step으로 분리하거나 이 지원 경계를 검토해야 한다. 범용 shell 해석기를 추가하는 방식으로 통과시키지 않는다.

별도 Codex 리뷰 미호출. D087 실제 계측/PR206 승인된 merge 후 main CI 확인을 우선하며 새 실패가 나오면 이 작업을 멈추고 대응한다.

## 구현 상태

기존4 shell lint는 byte불변이다. 새 helper2개/기존 policy run 앞의2줄만 구현했다. literal 지원은 선행 control/exit/function block 전의 단순 command이며 heredoc/multiline quote block은 증거에서 제외한다. gate의 기존 !cancelled 조건만 별도 지원하고 disabled/continue-on-error 소비자는 제외한다. writing 예외는 ship fenced command의 실제 소비자가 필요하다.

최소 초기 wiringCLI method와 최종 namespace local-render method만 개발 확인했고 현재 정상 배선 CLI도 PASS다. 최종추가된 new-lint 정상/누락과 disabled job 대조, 정식6methods/10poison은 Actions 대기다. 체크박스는 정식검증 후 갱신하며 현재 전체통과를 주장하지 않는다.
