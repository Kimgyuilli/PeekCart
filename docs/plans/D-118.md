# D-118 — main push 이미지 publish 의 원격 이미지 검사가 Docker 29 러너에서 실패한다

## 명제

containerd 이미지 저장소(Docker 29, `ubuntu-latest` = ubuntu-26.04)에서 `scripts/ci-image-identity.sh verify-remote` 가
같은 이미지를 불일치로 판정하면 미완이다. 기존 저장소에서 다른 원격 이미지를 일치로 판정해도 미완이다.

근거: main push CI 가 10-27(ubuntu-24.04, Docker 28.0.4)까지 성공하고 11-13(#261·#260, ubuntu-26.04, Docker 29.4.2)부터
publish 6개가 모두 실패했다. run 43369091718 의 payment-service 로그에서 기록한 이미지 ID 는 push manifest digest
`sha256:1f3641…` 와 같고 원격 config digest 는 `sha256:e186cf…` 다. containerd 저장소의 `docker image inspect .Id` 는
config digest 가 아니라 manifest digest 다.

## 작업 항목

- [x] P1. `verify-remote` 가 `docker info` 의 `DriverStatus` 로 containerd 저장소인지 판정한다. containerd 면 기록 ID 와
  push manifest digest 를, 아니면 기록 ID 와 원격 config digest 를 비교한다.
- [x] P2. self-test 에 containerd 저장소의 일치(원격 config digest 가 달라도 통과)와 불일치(다른 manifest digest 거부)를 더한다.

## 검증

- containerd 분기를 지운 변이 스크립트로 self-test 가 실패하는지 본다. 기존 저장소의 불일치 거부는 그대로 통과해야 한다.
- main push 의 publish 는 PR CI 에서 돌지 않는다. 실제 확인은 머지 뒤 main push CI 다.
