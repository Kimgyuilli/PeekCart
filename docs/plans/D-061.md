# D-061 환불 결과와 호출 순서 E2E

## 명제

실제 환불 SUCCEEDED/FAILED가 세 소비자에 종착하지 않거나 UNRESOLVED를 생산자가 발행했다고 오인하면 미완이다.
공유 E2E 검증 계약 변경으로 M. 프로덕션 정책/새 ADR 없이 ADR-0018을 검증한다.

| 코드 전제 | 확인 | 반영 |
|---|---|---|
| scenario C | 성공 Payment outbox까지만 확인 | 새 F에서 소비자 원장/알림까지 확인 |
| PaymentRefundService | UNRESOLVED는 회신 미발행 | 실제 Payment원장/outbox0과 합성UNRESOLVED회신 소비내성을 구분 |
| stub | ok/4xx/transient/already-full GET·POST 원장 제공 | 호출순서/횟수·멱등키 단언 |
| reconciliation | 5분 주기, lease5분 | CLAIMED 과거시각 seed 후 실제 스케줄러 GET-only 복구 관측, F budget확장 |

## 작업 항목

- [ ] P1. 성공/실패 실제 체인과 세 소비자의 eventId별 처리를 확인한다.
- [ ] P2. transient POST3, ALREADY POST/GET, reconciliation GET1/POST0 순서를 확인한다.
- [ ] P3. UNRESOLVED 생산자 미발행과 합성회신 소비자 무전이를 분리하고 lingering F를 꼬리에 고정한다.
- [ ] P4. 계약 매트릭스·음성 대조군·무료 CI 실제 스택 증거와 독립 검증/병합/완료기록.

## 검증

모든 DB 단언을 synthetic orderId/unique userId/eventId에 묶는다. 처리완료 원장이 존재한 뒤 알림0과 무전이를 확인해 단순시간대기 false-green을 막는다. manifest actual은 매트릭스와 정확일치. 순서·호출ledger 검사를 위반하는 경량 mutation selftest를 추가한다. 실제E2E는 CI에 맡기며 로컬heavy실행하지 않는다.
