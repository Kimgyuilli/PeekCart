# D-103: 리뷰 결과 렌더러 수용 계약

## 1. 명제와 코드 전제

`items:[{}]`, 알려지지 않은 severity 또는 잘못된 metadata가 정상 severity 표로 출력되거나, 비정상 결과가 사용법 오류 exit1/traceback으로 전달되면 미완이다. 과거 출력의 선택 필드 생략을 새 결과 스키마와 혼동해 거부해도 미완이다.

기준 main `f4ee03b97b0bec0c9be7cd3077911fb67b578b74`에서 다음 전제를 직접 확인했다.

| 전제 | 실제 source |
|---|---|
| 렌더러 검사 | scripts/codex-review-render.sh는 빈 파일/JSON parse/items 배열만 검사한다. 항목은 .get()으로 접근해 null은 AttributeError, 누락/알 수 없는 severity는 집계에서 사라진다. |
| 생산자 envelope | .claude/commands/{plan,work}.md는 각각 plan/diff-review.json을 output-schema로 사용한다. 초기 3ce748b와 현재 모두 run_id/summary/items 필수이고 앞 둘은 string이다. 새 model/timestamp 등의 metadata를 요구할 근거가 없다. |
| 항목 역사 | 초기 3ce748b의 공통 core는 id/severity/category/finding/suggestion이다. diff는 file/line도 있다. 268d994에서 scope/disposition 선택 속성이 추가됐고 6026d5e에서 required가 됐다. 렌더러와 기존 fixture는 생략된 선택 필드를 허용한다. |
| 타입/enum | id는 integer 최소1, line은 integer 최소0, severity P0/P1/P2, category 7종이다. string에 minLength, ID에 uniqueness 제약은 없다. scope/disposition은 알려진 enum이다. 생산자 schema는 추가 속성을 허용하지 않는다. |

등급 M: 공유 CLI의 입력 수용 계약 보강이다. 제품 모듈/외부 의존성/아키텍처/환경 변화가 없어 새 ADR은 필요하지 않다. D-104의 집계 출처·주석 사실 정정은 별도 후속이며 과거 raw corpus 부재를 숨기지 않는다.

## 2. 작업 항목

- [x] P1. envelope/core 항목 타입과 enum을 표 출력 전에 검증한다. 과거 file/line/scope/disposition 생략은 허용하되 존재하는 잘못된 값은 거부한다. 추가 metadata/빈 문자열 제한/ID uniqueness는 발명하지 않는다.
- [x] P2. 모든 비정상 결과를 exit2로 모으고 표/자동 통과/traceback이 나오지 않게 한다. CLI 사용법 오류 exit1과 정상 빈 배열/정상 항목 exit0은 구분한다. 정형 빈 배열은 실제 모델 실행 증거라고 설명하지 않는다.
- [x] P3. 정상 과거/현행 형식과 누락·null·P9·객체/스칼라·잘못된 타입/범위·빈 파일/파싱 오류를 paired fixture를 구성하고 잘못된 구현 대조를 추가한다. 기존 역사 회귀 oracle도 새 계약으로 갱신하되 원자료가 없으면 skip을 명시한다.
- [x] P4. 수용 계약과 역사 근거/실행 범위를 own 문서에 기록하고 기존 CI selftest에 정식 검증 경로를 연결한다. 공유 TASKS/PHASE/master는 root 소유로 유지한다.

## 3. 검증

최소 로컬 개발 확인만 수행하고 전체 selftest/음성 대조 및 PR checks는 Actions에서 실행한다. 실제 LLM/Codex 호출, Gradle/Docker/운영 요청은 없다. 실패 fixture는 exit2뿐 아니라 정상 severity 표·자동 통과·traceback 부재를 검사하고 정상 fixture는 출력 내용/optional columns/정렬을 검사한다. 잘못된 검증 제거 구현은 해당 fixture에서 실패해야 한다. 별도 Codex 리뷰 미호출. 정확 head 독립 검토와 전체 CI는 별도 대기다.

## 구현과 검증 상태

위 checkbox는 구현/fixture/CI 연결 완료를 뜻하며 전체 Actions 통과를 뜻하지 않는다. 표 출력 전 계약 검증과 buffered 출력, 비정상 결과 exit2를 구현했다. 신규8 method/8 mutants를 기존 shell selftest에 연결했고 synthetic jq oracle도 실행 대상에 포함했다. 최소 로컬2 method PASS(1.157s), jq oracle 정상/음성 각1입력과 syntax/AST/whitespace만 확인했다. 전체 selftest/CI와 정확 head 독립 검토는 draft PR에서 대기한다. 실제 corpus V9는 자료 부재로 별도 skip이다.

## 숫자 정밀도 독립 검토 반영

초기 f328 source는 binary float 반올림으로 raw id `1.0000000000000001` 또는 line `1e-999`를 integer로 잘못 받아들였다. parser가 Decimal 값을 보존하고 렌더러는 정수값과의 정확한 동등성으로 판정한다. 독립 oracle은 Decimal 부호/계수 digits/exponent와 trailing zero로 별도 판정한 뒤 id/line만 작은 정수 placeholder로 치환해 jq의 float 손실을 피한다. 거대한 지수는 전개하지 않는다. 정상 `1.0`, `10e-1`, `1e999`, `1e1000000`은 정수 호환으로 보존하며 bool/분수/underflow는 거부한다.

현재 전체 대상은 신규9 method와 10 wrong-implementation control(렌더러9/oracle1)이다. renderer float 재도입과 oracle float 재도입을 각각 거부하는 control을 추가했다. 최소 로컬 numeric1 method PASS(1.634s), 별도 oracle1 method PASS(0.500s)만 추가 실행했다. 전체 suite/controls 및 새 정확 head Actions는 아직 대기다. 초기 manifest는 f328에 귀속하고 수정 source/최소 결과는 numeric-review-manifest.json으로 분리한다.
