# D-050 — main 코드 주석의 계획서 내부 식별자 제거

## 1. 명제

main 코드 주석에 **계획서 안에서만 뜻이 통하는 식별자**(`§2.6-C` · `P15` · `④-c-2b-4a` · `PR3d-b` ·
`계획 리뷰 2R #5` 등)나 "~에서 제거했다/기존에는 ~였다" 류 이력 서술이 한 줄이라도 남아 있으면 미완이다.
코드만 읽는 사람이 그 주석의 근거를 복원할 수 없기 때문이다.

전제 검증(2026-09-29, 현재 코드 grep):

| 항목 | 결과 |
|---|---|
| 대상 규모 | `*/src/main/**` + `*.gradle` 중 해당 줄 약 520줄 · 약 200파일 · 11모듈 + 루트 빌드 스크립트 |
| 최다 밀집 | `peekcart-common-messaging` 138줄 (D-049 로 복제본이 하나로 합쳐진 뒤라 row 추정대로 감소) |
| Flyway SQL | `flyway-core 12.4.0` `ChecksumCalculator` 가 전 줄(주석 포함)을 CRC32 에 넣는다(javap 확인) → 적용된 마이그레이션 주석을 고치면 기존 DB 에서 validate 실패. **범위 밖** |
| 코드 아닌 적중 | `AuthController` OpenAPI `description` 1건(`PR3c`) — 문자열이지만 같은 성격이라 포함. `build.gradle` 로그 문자열 `[D-0xx]` 는 D-0xx 유지 규칙상 그대로 |

처리 규칙:

- **유지**: `ADR-NNNN`(뒤의 `§Dn`·`D2-c` 등 ADR 절 포함), `D-0xx`(TASKS·progress 에서 grep 되는 전역 ID, 사용자 결정 2026-09-29)
- **보정**: ADR 절인데 ADR 번호가 빠진 `§D8-3` 류 → 해당 ADR 을 찾아 `ADR-NNNN §D8-3` 으로 한정
- **제거**: 위 외의 계획 내부 식별자. 괄호 안 출처 표기면 괄호째 지운다
- **풀어 쓰기**: 식별자가 근거 역할을 하던 곳(예: "(④-c-1b 전례)")은 그 근거를 한 구절로 쓴다. 쓸 게 없으면 지운다
- **이력 → 현재형**: "PR4 에서 제거했다" 는 현재 상태 서술로 바꾸거나, 현재 동작 이해에 불필요하면 지운다
- 주석 문장 외 코드·포맷은 건드리지 않는다

## 3. 검증 방법

- **잔존 0**: 검사 스크립트(scratch)로 `*/src/main/**`(migration 제외) + `*.gradle` 을 훑어 적중 0.
  스크립트를 먼저 **실패 주입**으로 확인한다 — 임시 파일에 `// (계획 ④-c-2a P3, §2.5, PR3d)` 를 넣으면
  적중하고, `// ADR-0033 §D1 · D-049` 는 적중하지 않아야 한다
- **코드 무변경**: `git diff main` 의 변경 줄이 전부 주석 줄(`//` · `*` · `/*` · `#`)이거나 위 OpenAPI
  문자열 1건인지 스크립트로 판정. 다른 줄이 섞이면 실패
- **마이그레이션 무변경**: `git diff --stat main -- '*/db/migration/*'` 이 비어 있음
- **빌드**: `./gradlew compileJava processResources` 통과 (주석 경계 `*/` 파손 검출)

## 미해결

- 테스트 코드 주석(`src/test`)의 같은 식별자 — TASKS 행 범위가 main 이라 제외. 필요하면 별도 부채
- 재발 방지 lint(CI 편입) — 이번 검사 스크립트를 상시화할지는 결과 규모를 보고 판단. 이번 PR 범위 밖
