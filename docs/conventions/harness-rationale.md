# 하네스 커맨드 근거

`/plan`·`/work`·`/ship` 의 규칙이 왜 그렇게 정해졌는지를 모은 문서다. 커맨드 본문은 매 호출
컨텍스트에 실리므로 규칙만 남기고, 실측 수치와 사건 이력은 여기로 옮겼다(D-027 ①).
커맨드의 `(근거 R-...)` 가 아래 절을 가리킨다. 원래 이동한 근거에 D-104의 모집단/정정 주석을 반영했다. 수치의 재현 범위는 [D-104 근거](../plans/evidence/D-104/README.md)에 명시한다.

규칙을 바꾸거나 오적용을 의심할 때 이 문서를 읽는다. 규칙 자체의 정본은 커맨드다.

## R-plan-0

출처: `plan.md` 머리말

> **축소 이력 (2026-08-26)**: 12-step 상태머신(lock · `state.json` · gate TSV · metrics TSV · `pending_run` finalize)을 제거했다.
> 실측 근거 — 해당 기구는 결함 발견 0건이면서 런당 Bash 왕복 10~15회를 소모했다. 결함을 실제로 잡아온 것은 **Codex 리뷰 본체**이므로 그것만 남긴다.
> 이력은 `state.json` 이 아니라 **audit 파일과 git 이력**으로 남긴다.

## R-ship-0

> **축소 이력 (2026-08-30)**: 11-step 상태머신(lock · `state.json` · drift detector · resume cursor · gate events · archive)을 제거했다.
> 사유 — `/plan`·`/work` 는 2026-08-26 축소에서 이미 `state.json` 을 버렸는데 `/ship` 만 그것을 **필수 전제**로 남겨두어, Step 1 이 "state 가 없습니다. /work 를 먼저 완료하세요" 로 **정상 흐름을 차단**했다. 구현 ⑤(#94) 에서 실제로 이 불일치에 부딪혀 Step 1/10 을 건너뛰고 수행했다.

> 이 축소로 죽은 helper 들은 2026-09-18 정리에서 제거했다. `hpx_ship_pr_body_data`, `hpx_state_*`, `hpx_lock_*`, `hpx_gate_events_*`, `hpx_diff_absorption_status` 등 51개가 대상이었고 `lock.sh`·`state.sh`·`sync.sh` 는 파일째 삭제했다. 이력은 git 에 남는다.
