# 커밋 / PR 문체 규약

커밋 메시지와 PR 본문에 적용한다. 코드 주석과 설계 문서는 대상이 아니다.

기계로 검사 가능한 부분은 `scripts/writing-lint.sh` 가 강제한다. 톤은 검사할 수 없으므로
아래 예시로 전달한다.

## 1. 금지 문자

| 대상 | 대체 |
|---|---|
| em dash, en dash | 쉼표, 마침표, 괄호로 문장을 나눈다 |
| 화살표 (→ ← ↔ ⇒) | 말로 푼다. "A 에서 B 로", "A 때문에 B" |
| 수학 기호 (∧ ∨ ⊃ ≥ ≤ ≠ ×) | 말로 푼다. "이상", "배", "그리고" |
| 이모지 | 표에서는 완료, 대기, 미해결 같은 텍스트 |
| Claude 세션 링크, Co-Authored-By | 붙이지 않는다 |

`docs/TASKS.md` 의 상태 이모지는 예외다. 기존 인덱스 규약이고 스캔 용도라 유지한다.
이 규약은 커밋과 PR 에만 적용되므로 TASKS.md 는 애초에 검사 대상이 아니다.

세션 링크는 전역 설정 `attribution.sessionUrl: false` 로 이미 차단돼 있다. lint 는
설정이 풀렸을 때를 대비한 이중 방어다.

## 2. 제목

```
<type>(<scope>): <무엇을 했는지>
```

- `type` 은 feat, fix, refactor, test, docs, chore 중 하나
- 50자 내외. 60자를 넘으면 경고한다
- 명사형으로 끝낸다. 서술 종결("~한다", "~했다")은 쓰지 않는다
- 증상과 처방을 한 제목에 욱여넣지 않는다. 제목은 결론 하나다
- 추적 태그(부채 ID, ADR 번호, PR 번호)는 제목이 아니라 본문 마지막 줄에 둔다

## 3. 본문

- 어미를 하나로 고정한다. 커밋 본문은 "~함" 또는 "~임", PR 본문은 "~습니다"
- 한 문단은 3~4줄. 문단 사이를 비운다
- 볼드는 한 섹션에 최대 2개. 전부 강조하면 아무것도 강조되지 않는다
- 백틱은 식별자와 경로에만 쓴다. 한글 문장을 백틱으로 감싸지 않는다
- 사실을 적는다. 반전이나 수사("한 단계 더 나쁘다", "측정이 먼저 있었다")는 쓰지 않는다
- 작업 중의 시행착오와 자기 서사는 audit 파일에 둔다. 커밋과 PR 은 결과를 적는 자리다

## 4. 예시

### 제목

나쁜 예. 실제 커밋 `04164db` 이다.

```
fix(product): 분산 락이 커밋을 감싸지 못한다 — 재고 동시성을 @Version 하나로 (D-025, ADR-0025)
```

em dash 로 증상과 처방 두 문장을 이었고, 서술 종결이며, 추적 태그가 제목을 차지하고,
길이가 70자를 넘는다.

좋은 예.

```
fix(product): 재고 동시성 제어를 낙관적 락으로 단일화
```

### 본문

나쁜 예. 실제 PR #123 본문의 한 대목이다.

```
- **락 구간에 쓰기가 아예 없었다.** `InventoryService.decreaseStock` 은 조회 +
  managed 엔티티 필드 변경뿐이고 `save`/`flush` 가 없다. 참여 트랜잭션이라 UPDATE 는
  커밋 flush 에 나간다 — 락이 감싼 것은 **읽기뿐**이었다. "커밋을 못 감쌌다" 보다
  한 단계 더 나쁘다.
```

한 항목에 볼드가 둘이고, em dash 가 있고, 마지막 문장이 사실이 아니라 수사다.

좋은 예.

```
락 구간에 쓰기가 없었습니다. InventoryService.decreaseStock 은 조회와 managed 엔티티
필드 변경뿐이고 save 나 flush 호출이 없습니다. 참여 트랜잭션이라 UPDATE 는 커밋 시점의
flush 에 나가므로, 락이 실제로 감싼 구간은 읽기뿐입니다.
```

### 커밋 본문 전체

```
fix(product): 재고 동시성 제어를 낙관적 락으로 단일화

Redis 분산 락과 JPA 낙관적 락이 중복으로 걸려 있었으나, 분산 락은 트랜잭션 커밋
이전에 해제되어 실제로는 읽기 구간만 보호하고 있었음. GKE 3레플리카 측정에서 락
획득 실패 0건, 낙관락 충돌 7건으로 분산 락의 기여가 없음을 확인함.

InventoryLockFacade 를 제거하고 @Version 단일 수단으로 통일함. 재시도 백오프에
지터를 추가해 동시 충돌 소비자가 같은 시점에 재시도하는 문제를 함께 해소함.

Refs: D-025, ADR-0025
```

## 5. PR 본문의 리뷰 이력

등급과 리뷰 상태를 사실대로 적는다. 돌리지 않은 리뷰를 "라운드 0, 미실시"로 적지 않는다.
그것은 남은 일이 아니라 절차상 없는 단계이거나 의도적 판단이다.

```markdown
## 리뷰 이력

- 등급: S
- 계획 리뷰: 해당 없음(등급 S)
- diff 리뷰: 해당 없음(등급 S)
```

상태값 넷의 정의는 `.claude/commands/work.md` §9 에 있다. `미결` 만 미충족 항목으로 올린다.

## 6. 검사

```bash
scripts/writing-lint.sh --commits "$(git merge-base HEAD origin/main)..HEAD"
scripts/writing-lint.sh --file .cache/pr-body-<task-id>.md
scripts/writing-lint.sh --title "chore(k8s): base MySQL CPU 상한 2000m 승격"
scripts/writing-lint.sh --msg .git/COMMIT_EDITMSG
scripts/writing-lint.sh --self-test
```

`--msg` 는 `.githooks/commit-msg` 가 커밋 시점에 자동으로 돌린다. `--commits` 로는
그 자리를 대신할 수 없다. 그쪽은 **이미 만들어진** 커밋을 읽으므로 커밋 객체가 없는
시점에는 쓸 수 없다. `--file` 도 안 된다. `body` 모드라 제목 형식을 보지 않고, 대신
PR 본문 전용인 `~습니다` 검사를 돌려 커밋 규약(`~함`/`~임`)을 전부 오탐한다.

`--msg` 가 검사하지 않는 것: git 이 붙이는 주석(`#` 줄), `verbose` 커밋의 scissors
(`# ---- >8 ----`) 이후 diff, 그리고 머지·revert·fixup·squash 메시지다. 앞의 둘은
사용자가 고칠 수 없는 텍스트이고, 뒤는 제목이 git 이나 도구가 정하는 자리라
`<type>(<scope>)` 규약 대상이 아니다.

`/ship` 이 PR 본문 승인 게이트 직전에 자동으로 돌린다. 오류는 종료 코드 1, 경고는 0 이다.
경고는 고치는 편이 낫지만 진행을 막지는 않는다.

### lint 가 덮는 것

| 항목 | 커밋 | PR 본문 | PR 제목 |
|---|---|---|---|
| 금지 문자(em dash, 화살표, 수학 기호, 이모지) | 오류 | 오류 | 오류 |
| 귀속 트레일러 | 오류 | 오류 | 오류 |
| 제목 형식 | 오류 | 해당 없음 | 오류 |
| §3 어미("~습니다") | 해당 없음 | **오류** | 해당 없음 |
| §3 볼드 최대 2개 | 경고 | **오류** | 해당 없음 |
| 제목 길이, 서술 종결 | 경고 | 해당 없음 | 경고 |
| 추적 태그 위치 | 경고 | 해당 없음 | **오류** |

커밋 메시지 검사는 `commit-msg` 훅이 커밋 시점에 돌린다. `/ship` Step 4-1 도 같은
규칙을 보지만 그때는 커밋이 이미 쌓여 있어 `cherry-pick` 재작성이 필요하다. D-029 에서
커밋 5개를 통째로 다시 썼고, 위반은 `infra(k8s)` 처럼 허용 type 이 아닌 제목과 em dash,
화살표였다. 전부 커밋 시점에 알 수 있는 것이었다.

PR 제목 열이 뒤늦게 생긴 경위: PR [#131](https://github.com/Kimgyuilli/PeekCart/pull/131)
제목이 `(D-029)` 를 달고 나갔다. `--commits` 가 커밋 제목에서 같은 위반을 경고로 잡아
고쳤으나, `gh pr create --title` 은 검사 경로가 아예 없어서 고친 직후 같은 자리에서
재발했다. 추적 태그를 제목 모드에서 **오류**로 둔 것은 볼드 밀도와 같은 판단이다.
경고로 두면 넘어가고, 실제로 넘어갔다.

부채 ID 정규식도 이때 함께 고쳤다. `[A-Z]{2,}-\d+` 였어서 `ADR-0027` 과 `#131` 은
잡으면서 이 프로젝트의 `D-029` 는 **한 번도 잡지 못했다**. 대문자 한 글자 접두사다.

### lint 가 덮지 않는 것 — 눈으로 봐야 한다

**lint 통과는 규약 준수가 아니다.** 아래는 기계로 판정할 수 없어 검사에서 빠져 있다.
본문을 사람에게 보이기 전에 이 셋을 직접 확인한다.

- **§3 수사·반전 금지** — 섹션 제목이 주장이나 서사가 아니라 대상을 가리키는지.
  나쁜 예: `### 헤드라인 숫자를 바꿨다`, `### 되돌림 블록이 해석을 정정했다`.
  좋은 예: `### 배속 판정 기준`, `### MySQL CPU 상한`
- **§3 시행착오·자기 서사 배제** — 작업 중 무엇이 깨졌고 어떻게 고쳤는지는 audit 파일 몫이다.
  PR 은 결과를 적는 자리다. "그대로 갔으면 틀렸을 것이다" 류는 PR 에 쓰지 않는다
- **문단 길이와 사실성** — 3~4줄 유지, 검증하지 않은 인과를 단정하지 않았는지

이 절이 생긴 경위: PR [#129](https://github.com/Kimgyuilli/PeekCart/pull/129) 본문이 46문장 전부
"~다." 로 나갔는데 lint 는 통과를 냈다. 어미 검사가 없었고, `서술 종결` 검사는 커밋 제목 전용
(`mode == 'title_body'`)이라 PR 본문에는 돌지 않았다. 어미와 볼드는 그때 lint 로 옮겼고,
나머지 셋은 기계로 못 잡으므로 **무엇이 안 덮이는지를 여기 적어 둔다**.
