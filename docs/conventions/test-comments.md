# 테스트 주석의 의미와 출처

테스트 주석은 무엇을 검증하는지, 어떤 잘못된 구현을 막는지, fixture나 검증 도구를 왜 선택했는지 설명한다. 계획 내부의 `P24`, `④-c-2b-4a`, `PR3d`, `리뷰 1R #3`만으로 출처를 대신하지 않는다. 이미 같은 문장에 의미가 있으면 중복 표식을 지우고, 의미가 표식에만 있으면 현재 계약이나 실패 경로를 풀어 쓴다.

다음 출처는 유지한다.

- `ADR-0022 §D4`처럼 문서와 절이 식별되는 근거. bare `§11`은 문서 이름을 붙이거나 의미로 바꾼다.
- `D-025`, `L-013` 같은 저장소 전역 부채 ID와 실제 파일·클래스·method 참조.
- ADR이 정의한 `S1`, `P1-D`와 같은 표면. ADR 번호로 소유 문서를 한정한다.
- 같은 테스트 파일이 시나리오와 함께 정의한 `V-P4-1`이나 계약 식별자 `[SAGA-P1-BASEURL-OWN]`. 외부 계획을 읽어야만 뜻을 아는 표식과 구분한다.

작업 이력은 현재 행동 설명으로 바꾸거나 구체적인 역사 문서에 연결한다. 특히 '이 PR에는 진입점이 없다' 같은 상대적 시점 표현은 이후에도 남는 코드 주석에 쓰지 않는다. 과거 실패에서 배운 이유는 보존하되 그 실패의 메커니즘을 함께 설명한다.

D-102 정리 범위는 Java `src/test`의 comment다. DisplayName, assertion 문자열, method 이름과 로컬 시나리오 구분은 실행 토큰이므로 이 작업에서 바꾸지 않았다. 정리 결과와 예외는 [D-102 inventory와 재현 검사](../plans/evidence/D-102/README.md)에 있다. 다른 언어·testFixtures·main의 주석까지 검사했다고 해석하지 않는다.

## 재발 감시와 CI 후속 조건

현재 검색 baseline은 [accepted-candidates.tsv](../plans/evidence/D-102/accepted-candidates.tsv)의 20개 comment 적중과 그 보존 사유다. 줄번호가 이동했다는 이유만으로 재발로 세지 않고 파일·주석 내용·소유 출처를 확인한다. 후보를 자동으로 모두 부채 처리하지 않는다.

테스트 주석을 추가하거나 수정하는 작업에서 `python3 docs/plans/evidence/D-102/check.py --scan`을 실행해 기존 baseline 밖의 후보를 읽는다. 새 marker가 ADR·전역 부채·구체 파일이나 파일 내 시나리오로 의미를 복원할 수 없다면 **새 opaque comment 재발 1건**으로 기록한다. 해당 작업의 task/PR에 파일·줄·marker·발생 commit을 남기고 별도 CI lint 후속 항목을 연다. D-102의 기존 제외 범위에 돌려놓거나 baseline에 설명 없이 추가하지 않는다.

CI lint 후속의 완료 조건은 comment와 문자열을 구분하고, 이 문서의 유효한 출처를 보존하며, 새 opaque comment 변이는 실패시키고 문자열/ADR/전역 ID 대조군은 통과시키는 것이다. 이 조건은 D-088의 일반 lint 생존·배선 검사와 별개다. 아직 새 재발을 관찰한 결과가 아니므로 이번 PR에서 CI의 기존 job이나 전체 lint 정책을 바꾸지는 않는다.
