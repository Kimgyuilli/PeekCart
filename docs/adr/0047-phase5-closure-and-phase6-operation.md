# ADR-0047: Phase 5 마감과 Phase 6 운영 방식 (수요형 유지, 열린 행 이월, 2026-10-25 범위 결정)

- **Status**: Accepted
- **Date**: 2026-10-27
- **Deciders**: 프로젝트 오너 (2026-10-26 질문지 0-1·3-5, `docs/evidence/D-116/decisions.md`)
- **관련 Phase**: Phase 6

## Context

### 종결 조건이 없다는 결정과 마감 요청

Phase 5 는 2026-09-22 에 순서표 없이 시작했다(#134). 그때 세 문서가 단계가 닫히지 않는다는 것을 결정으로 적었다.

- `docs/progress/PHASE5.md` "Phase 5 는 무엇이 다른가": Exit Criteria 가 없다. 소진할 목록이 없으므로 단계가 종결되지 않고,
  `docs/TASKS.md` 의 열린 표가 곧 현황이다.
- `docs/TASKS.md` 현재 단계 절: 단계 종결 조건 없음. Phase 4 처럼 순서표 소진으로 닫히지 않는다.
- `docs/07-roadmap-portfolio.md` §16: Phase 5 의 작업 목록도 Exit Criteria 도 적지 않는다.

2026-10-26 사용자가 Phase 5 를 끝내고 다음 단계로 넘어가겠다고 요청했다(`docs/evidence/D-116/decisions.md` 요청 원문). 순서표
소진이라는 닫는 방법이 없으므로 이 요청은 위 결정과 충돌한다. 조사 C 가 이 충돌을 질문 Q1 로 올렸고
(`docs/evidence/D-116/survey-C-docs.md` §4·§10), 질문지 0-1 에서 사용자는 Phase 6 선언을 골랐다. 답은 "다음단계는 수요형이고
남은 부채도 이월합니다" 다.

### 단계 전환에 쓸 규칙

Phase 1~4 는 순서표를 소진해 닫았다. Phase 4 에서 5 로 넘어갈 때는 종결 엔트리와 TASKS 헤더 갱신(#133), 단계 줄 전환과
`PHASE5.md` 신설(#134)이 그 일을 했다(조사 C §3-2). 수요형 단계를 닫은 선례는 없고, 열린 11행(D-065·D-078·D-084·D-108·
D-109~D-115)은 어떤 단계 조건에도 묶여 있지 않다(조사 C §4).

- 하네스는 `docs/TASKS.md` 의 `## 현재 단계:` 줄에서 Phase 번호를 읽어 `docs/progress/PHASE{N}.md` 를 연다
  (`scripts/harness-context.sh`). `/ship` 8단계와 `/done` 7단계도 `PHASE{N}.md` 에 기록한다. 단계를 닫는 PR 은 이 줄을 바꾸므로,
  그 PR 에서 `PHASE{N}.md` 는 이미 다음 단계 파일이다.
- `PHASE5.md` 의 엔트리는 세 구역(작업 이력 앞, 옛 형식 `## <제목> (…, YYYY-MM-DD)`, 새 형식 `## YYYY-MM-DD — <제목>`)에
  나뉘었다. 앞의 두 구역은 최신이 위, 새 형식 구역은 오래된 것이 위여서 종결 엔트리가 들어갈 자리가 정해져 있지 않았다
  (조사 C §3-3·§7-1).

### 범위 결정의 기록 위치

2026-10-25 사용자 범위 결정은 TASKS 행의 상태 칸(열린 D-065·D-084·D-108, 완료된 D-064)과 `PHASE5.md` 의 2026-10-25·
2026-10-26 엔트리에만 있다. 같은 날의 조회 상한 1 유지는 ADR-0046 이 적는다. 상태 칸은 행이 진행되면 고쳐 쓰는 자리이고,
단계를 바꾸면 다이제스트는 `PHASE5.md` 를 읽지 않는다. 질문지 3-5 에서 사용자는 이 범위 결정과 Phase 5 마감 결정을 ADR 로
올리기로 했다.

## Decision

Phase 5 를 사용자 결정으로 닫고, Phase 6 도 수요형으로 열어 열린 행을 그대로 넘긴다. 단계 전환의 이월·기록 규칙과 2026-10-25
범위 결정을 이 ADR 이 기록한다.

### D1. Phase 5 는 사용자 결정으로 2026-10-27 에 닫는다

Phase 5 는 Exit Criteria 가 아니라 사용자 결정(질문지 0-1)으로 닫는다. 닫는 시점은 마감 정리(D-116)가 끝나는 2026-10-27 이고,
Phase 5 의 기간은 2026-09-22~2026-10-27 이다. `PHASE5.md` "Phase 5 는 무엇이 다른가" 의 "단계가 종결되지 않는다" 는 그 시점의
기록이라 고치지 않는다. Phase 5 를 닫는 근거는 이 ADR 과 `PHASE5.md` 의 종결 엔트리다.

### D2. Phase 6 도 수요형이다

Phase 6 에는 순서표·작업 목록·Exit Criteria 를 두지 않는다. 필요하다고 판단한 시점에 항목을 추가하고 그때 착수한다. 추적 축은
`docs/TASKS.md` 의 D- 단일 표이고, 번호는 새로 시작하지 않는다(다음 번호는 TASKS 표와 `docs/progress/TASKS-done.md` 의 최대
번호 + 1). 단계는 사용자 결정으로 닫고, 그 결정을 ADR 로 남긴다.

### D3. 열린 행은 그대로 넘긴다

단계를 바꿀 때 열린 행은 ID·본문·상태를 바꾸지 않고 `docs/TASKS.md` 에 둔다. 새 단계 파일의 이월 표가 이월 시점의 상태를
적고, 현황은 TASKS 가 정본이다. 완료 행은 단계와 무관하게 `docs/progress/TASKS-done.md` 표 맨 아래에 쌓고, 단계별 TASKS
아카이브는 만들지 않는다. Phase 5 에서 6 으로 넘기는 행은 열린 11행이다. D-116 은 마감 정리가 끝나며 완료 행으로 옮긴다.

### D4. 단계를 닫는 PR 의 기록은 닫히는 단계 파일에 둔다

단계를 닫는 PR 의 기록은 닫히는 단계 파일 끝의 종결 엔트리에 둔다. 그 PR 이 `## 현재 단계:` 를 다음 단계로 바꿔도 새 단계
파일에는 적지 않는다. 새 단계 파일의 작업 이력은 비워 두고, 첫 엔트리는 다음 작업이 쓴다.

단계 파일의 엔트리는 `## YYYY-MM-DD — <제목>` 한 형식으로 오래된 것부터 아래로 쌓는다. `PHASE5.md` 의 옛 형식 헤딩과 최신이
위인 두 구역은 이 형식과 방향으로 재정렬한다(질문지 3-3). 재정렬은 헤딩의 날짜를 앞으로 옮기고 절의 순서를 바꾼다. 엔트리
본문은 고치지 않는다.

### D5. 2026-10-25 범위 결정

2026-10-25 사용자 결정의 내용은 다음과 같다. 출처는 `PHASE5.md` 의 엔트리 "2026-10-25 — PG·운영 제외 부채 병렬 처리와 재측정
준비", "2026-10-25 — 마지막 재측정 준비와 조회 캐시 결정", "2026-10-26 — Toss 테스트 환경 실호출 검증", "2026-10-26 — D-108
마지막 재측정 세션" 과 `docs/TASKS.md` 의 D-065·D-084·D-108 행 상태 칸, `docs/progress/TASKS-done.md` 의 D-064 행이다.

1. PG·운영이 엮인 항목(D-064, D-084, D-065 ④, D-065 ③ 의 운영 적용 증빙)을 범위에서 뺐다.
2. D-065 는 ⏸ 보류다. 운영 환경이 엮인 ④ 운영 표본과 ③ 의 운영 writer 정지·전환 증빙·운영 DDL 적용을 범위에서 뺐다. ③ 의
   코드 몫(4서비스 `record_kind`·`root_record_id` NOT NULL contract 와 DDL 전 가드)은 #244 로 병합했다.
3. D-084 는 ⏸ 보류다. 재개 조건은 "영구 404 의 PG 발급 무과금 증빙 원천·형식 확보" 다.
4. D-064 는 2026-10-25 사용자 결정으로 보류를 좁혀 열었고, 좁힌 범위(Toss 테스트 환경 실호출)에서 #249 로 완료했다
   (2026-10-26).
5. 측정은 측정을 막는 부채만 해결하고 과금 세션 1회(S3 만)로 끝낸다. 그 1회는 2026-10-25 17:32~22:38Z 의 세션이다(#250).
   D-109 ⑤ 의 GKE 검증은 이 세션을 전제했지만 세션 범위에 들지 않았고, 추가 과금 세션이 없어 검증 방법을 다시 정해야 한다.
6. D-108 ③(order-service liveness 프로브)은 범위 밖이다. 측정을 막지 않으므로 측정 overlay 의 완화로 처리하고 base·운영 프로브
   정책은 정하지 않는다. D-108 은 ③ 만 남은 ◐ 부분 완료다.
7. 조회 DB 진입 상한 1 유지도 2026-10-25 결정이다. 결정과 근거는 ADR-0046 D1 이 적는다.

D-065·D-084·D-108 은 D3 대로 상태 칸을 그대로 두고 Phase 6 으로 넘긴다.

## Alternatives Considered

### Alternative A: Phase 5 를 닫지 않고 기록만 분리 (조사 C Q1 (a))
- **장점**: 종결 조건이 없다는 2026-09-22 의 결정을 지킨다. `## 현재 단계:` 와 `PHASE{N}.md` 앵커가 바뀌지 않는다.
- **단점**: 사용자 요청(Phase 5 를 끝내고 다음 단계로)과 맞지 않는다. 기록만 나누면 Phase 5 가 어디서 끝나는지 정한 결정이 남지
  않는다.
- **기각 사유**: 질문지 0-1 에서 사용자가 Phase 6 선언을 골랐다.

### Alternative B: Phase 6 에 로드맵과 Exit Criteria 를 둔다
- **장점**: 단계를 닫는 조건이 처음부터 정해진다. Phase 1~4 처럼 순서표 소진으로 닫는다.
- **단점**: 열린 11행을 순서표로 묶으려면 우선순위와 범위를 먼저 정해야 한다. 07 §16 이 적었듯 작업 목록을 적으면 그것이 로드맵이
  된다.
- **기각 사유**: 질문지 0-1 의 답이 "다음단계는 수요형" 이다(해석: 로드맵·Exit Criteria 없음).

### Alternative C: 열린 행을 아카이브하고 Phase 6 에서 다시 등록한다
- **장점**: Phase 6 의 TASKS 표가 빈 상태로 시작해 단계 경계가 표에서 보인다.
- **단점**: 같은 번호로 다시 쓰면 한 ID 의 본문이 두 곳에 생긴다. 새 번호를 주면 ADR 이 D- 번호로 행의 근거를 가리키는
  관계(`docs/progress/TASKS-done.md` 머리말)가 끊긴다. ADR-0022·ADR-0043 은 D-065 를, ADR-0040 은 D-084 를, ADR-0046 은
  D-078·D-108 을 가리킨다.
- **기각 사유**: 질문지 0-1 의 답이 "남은 부채도 이월합니다" 이고, 행의 근거를 가리키는 참조를 끊는다.

## Consequences

### 긍정적 영향
- Phase 5 의 기간(2026-09-22~2026-10-27)과 닫은 근거를 이 ADR 한 곳에서 읽는다.
- 열린 행의 ID·본문·상태가 그대로라 ADR·계획서·증적의 D- 참조가 같은 행을 가리킨다.
- 2026-10-25 범위 결정이 행의 상태 칸이 바뀌거나 다이제스트가 `PHASE5.md` 를 읽지 않게 돼도 남는다.
- 단계 파일의 엔트리가 한 형식·한 방향이라 최신 엔트리와 종결 엔트리가 파일 끝에 온다.

### 부정적 영향 / 트레이드오프
- 단계 경계가 작업 내용이 아니라 결정 시점이다. 열린 11행은 두 단계에 걸치고, 행 하나의 이력이 `PHASE5.md` 와 `PHASE6.md` 에
  나뉜다.
- `PHASE5.md` 의 헤딩 40개와 절 순서가 바뀐다. 이 파일의 줄 번호를 인용한 조사 보고서(`docs/evidence/D-116/` 의 survey-B·C·D)와
  `docs/plans/done/D-052.md` 는 각자의 base 커밋 기준으로만 맞는다.
- D4 의 기록 위치는 `/ship`·`/done` 지시문에 없고 이 ADR 에만 있다(엔트리 형식과 방향은 단계 파일의 형식 선언에도 있다).
  지시문은 `PHASE{N}.md` 를 그대로 가리키므로 다음 단계 전환 때도 이 ADR 을 읽어야 한다.
- 하네스가 `## 현재 단계:` 의 번호로 `PHASE{N}.md` 를 열므로 단계를 바꾸는 커밋은 새 단계 파일을 함께 둬야 한다. 없으면
  다이제스트가 파서 고장으로 끝난다.

### 후속 결정에 미치는 영향
- Phase 6 을 닫을 때도 사용자 결정과 ADR 이 필요하다. 그 ADR 은 D3·D4 를 따르거나 바꾼다.
- 다이제스트는 날짜(`YYYY-MM-DD`)가 있는 `## ` 헤딩을 엔트리로 센다. 단계 파일의 틀 절(무엇이 다른가, 이월 항목, 작업 이력)
  헤딩에는 날짜를 넣지 않는다.
- D-065·D-084 를 다시 여는 일과 D-108 ③ 의 base·운영 프로브 정책은 이 ADR 이 정하지 않는다. 행의 재개 조건과 새 사용자
  결정으로 다룬다.
